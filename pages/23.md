## 111. 요세푸스 문제

1세기 유대 역사가 요세푸스는 로마군에 포위된 동굴에서 동료들과 원을 이루어 순서대로 목숨을 끊기로 했지만, 자리를 잘 골라 마지막까지 살아남았다는 이야기를 남겼습니다. 이 일화에서 유명한 수학 문제가 나왔습니다.

**문제** 1번부터 N번까지 N명이 원을 이루어 앉아 있습니다. 1번부터 세기 시작해 K번째 사람을 원에서 빼고, 그다음 사람부터 다시 세어 K번째 사람을 빼는 일을 모두 빠질 때까지 반복합니다. 빠지는 순서를 출력하십시오.

**제한** 1 ≤ K ≤ N ≤ 5000

**예제 입력**

```
7 3
```

**예제 출력**

```
3 6 2 7 5 1 4
```

<details>
<summary>💡 힌트 보기</summary>

리스트와 현재 위치 `idx`를 두고, `idx = (idx + K - 1) % 남은 인원`을 계산한 뒤 `pop(idx)` 하십시오. pop한 자리에는 다음 사람이 오므로 idx는 그대로 다음 출발점이 됩니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n, k = map(int, input().split())
people = list(range(1, n + 1))
idx = 0
order = []
while people:
    idx = (idx + k - 1) % len(people)
    order.append(people.pop(idx))
print(*order)
```

원을 리스트로 흉내 내고 나머지 연산으로 끝과 처음을 잇는 것이 시뮬레이션의 요령입니다. `pop(idx)`는 뒤쪽 원소들을 한 칸씩 당기므로 매번 최대 N번 이동하여 전체 O(N²)입니다. N = 5000에서는 충분히 빠릅니다. 마지막 생존자 한 명만 알고 싶다면 J(n) = (J(n−1) + k) % n이라는 점화식으로 O(N)에 구할 수 있습니다. 시뮬레이션 없이 수학으로 건너뛰는 셈입니다.

</details>

## 112. 콜라츠의 우박수

짝수이면 2로 나누고 홀수이면 3을 곱해 1을 더합니다. 1937년 로타르 콜라츠가 제기한 이 추측, 곧 어떤 자연수에서 시작해도 결국 1에 이른다는 명제는 아직 아무도 증명하지 못했습니다. 수열이 우박처럼 오르내린다고 해서 '우박수'라고도 부릅니다.

**문제** 자연수 n을 입력받아 **1에 도달하기까지의 단계 수**와 **그 과정에서 나타난 가장 큰 수**를 출력하십시오.

**제한** 1 ≤ n ≤ 10⁹

**예제 입력 1**

```
6
```

**예제 출력 1**

```
8 16
```

**예제 입력 2**

```
27
```

**예제 출력 2**

```
111 9232
```

<details>
<summary>💡 힌트 보기</summary>

`while n != 1:` 안에서 규칙을 적용하고, 단계 수와 최댓값을 함께 갱신하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
steps, peak = 0, n
while n != 1:
    n = n // 2 if n % 2 == 0 else 3 * n + 1
    peak = max(peak, n)
    steps += 1
print(steps, peak)
```

27이라는 작은 수가 9232까지 치솟는 모습이 이 추측의 기묘함을 잘 보여 줍니다. 숨은 테스트의 837799는 백만 미만에서 가장 오래 걸리는 수(524단계)이고, 670617279는 10억 미만에서 가장 오래 걸리는 수(986단계)입니다. 콜라츠 추측은 2⁶⁸ 근처까지 컴퓨터로 확인되었지만 증명은 여전히 없습니다. 에르되시는 '수학은 아직 이런 문제를 다룰 준비가 되어 있지 않다'고 말했다고 전해집니다.

</details>

## 113. 생명 게임

1970년 수학자 존 콘웨이가 고안한 '생명 게임'은 단 네 줄의 규칙만으로 움직이고, 번식하고, 스스로를 복제하는 놀라운 무늬들을 만들어 냅니다. 이 게임은 튜링 완전하다는 것, 곧 어떤 계산이든 할 수 있다는 것이 증명되어 있습니다.

**문제** R×C 격자의 각 칸은 살아 있거나(`#`) 죽어 있습니다(`.`). 한 세대가 지나면 모든 칸이 동시에 다음 규칙에 따라 바뀝니다. 이웃은 가로·세로·대각선의 8칸이며, 격자 밖은 언제나 죽은 칸입니다.

- 산 칸은 산 이웃이 2개 또는 3개이면 살아남고, 아니면 죽습니다.
- 죽은 칸은 산 이웃이 정확히 3개이면 살아납니다.

첫째 줄에 R, C, T, 이어서 R줄에 격자가 주어질 때 T세대 뒤의 격자를 출력하십시오.

**제한** 1 ≤ R, C ≤ 50, 0 ≤ T ≤ 100

**예제 입력 1**

```
5 5 1
.....
..#..
..#..
..#..
.....
```

**예제 출력 1**

```
.....
.....
.###.
.....
.....
```

**예제 입력 2**

```
6 6 4
.#....
..#...
###...
......
......
......
```

**예제 출력 2**

```
......
..#...
...#..
.###..
......
......
```

<details>
<summary>💡 힌트 보기</summary>

새 격자를 따로 만들어 계산해야 합니다. 원래 격자를 고치면서 계산하면 '동시에' 바뀐다는 규칙이 깨집니다. 이웃은 `dr`, `dc`가 −1, 0, 1인 8가지 조합(0, 0 제외)입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
r, c, t = map(int, input().split())
g = [list(input()) for _ in range(r)]
for _ in range(t):
    new = [["."] * c for _ in range(r)]
    for i in range(r):
        for j in range(c):
            alive = 0
            for di in (-1, 0, 1):
                for dj in (-1, 0, 1):
                    if (di or dj) and 0 <= i + di < r and 0 <= j + dj < c and g[i + di][j + dj] == "#":
                        alive += 1
            if alive == 3 or (alive == 2 and g[i][j] == "#"):
                new[i][j] = "#"
    g = new
print("\n".join("".join(row) for row in g))
```

예제 1은 세 칸짜리 막대가 세로와 가로를 오가는 '깜빡이'이고, 예제 2는 네 세대마다 대각선으로 한 칸씩 움직이는 '글라이더'입니다. 규칙 두 줄은 '산 이웃이 3이면 살고, 2이면 현재 상태 유지'라는 한 줄로 합쳐집니다. 규칙을 다시 정리하면 코드가 짧아집니다. `(di or dj)`는 자기 자신(0, 0)을 빼는 조건입니다. 50×50 격자 100세대면 약 220만 번 검사하므로, 숨은 테스트도 넉넉히 통과합니다.

</details>

## 114. 달팽이 행렬

달팽이 껍데기처럼 바깥에서 안쪽으로 돌아 들어가는 배열은 방향 전환을 연습하기에 좋은 소재입니다. 89번 로봇의 방향 벡터가 여기서 다시 쓰입니다.

**문제** 자연수 n이 주어질 때 n×n 격자의 왼쪽 위에서 시작해 오른쪽 → 아래 → 왼쪽 → 위 순서로 시계 방향으로 돌며 1부터 n²까지 채운 행렬을 출력하십시오. 각 행의 수는 공백 하나로 구분합니다.

**제한** 1 ≤ n ≤ 100

**예제 입력**

```
4
```

**예제 출력**

```
1 2 3 4
12 13 14 5
11 16 15 6
10 9 8 7
```

<details>
<summary>💡 힌트 보기</summary>

한 방향으로 가다가 다음 칸이 격자 밖이거나 이미 채워져 있으면 오른쪽으로 90° 돌아가십시오. 방향 표는 `DR = [0, 1, 0, -1]`, `DC = [1, 0, -1, 0]`입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
DR, DC = [0, 1, 0, -1], [1, 0, -1, 0]
g = [[0] * n for _ in range(n)]
r = c = d = 0
for v in range(1, n * n + 1):
    g[r][c] = v
    nr, nc = r + DR[d], c + DC[d]
    if not (0 <= nr < n and 0 <= nc < n and g[nr][nc] == 0):
        d = (d + 1) % 4
        nr, nc = r + DR[d], c + DC[d]
    r, c = nr, nc
for row in g:
    print(*row)
```

'막히면 돈다'는 단순한 규칙 하나가 복잡한 경계 계산을 모두 대신합니다. 각 겹의 길이를 계산하는 방식보다 실수할 여지가 훨씬 적습니다. 마지막 칸을 채운 뒤에도 다음 칸을 계산하지만, 그 값은 쓰이지 않으므로 문제가 없습니다. n = 1일 때도 그대로 동작하는지 확인해 보십시오.

</details>

## 115. 완벽한 셔플

마술사이자 수학자인 퍼시 다이아코니스는 52장의 카드를 정확히 반으로 나누어 한 장씩 번갈아 끼우는 '완벽한 아웃 셔플'을 여덟 번 하면 카드가 원래 순서로 돌아온다는 사실로 유명합니다. 무작위처럼 보이는 셔플이 사실은 완벽하게 결정적이라는 것입니다.

**문제** 짝수 D장의 카드 더미가 있습니다. 아웃 셔플은 더미를 위쪽 절반과 아래쪽 절반으로 나눈 뒤, **위쪽 절반의 첫 장부터** 두 절반에서 한 장씩 번갈아 끼우는 것입니다. 원래 순서로 처음 돌아올 때까지 몇 번 셔플해야 하는지 출력하십시오.

**제한** 2 ≤ D ≤ 1000, D는 짝수

**예제 입력 1**

```
52
```

**예제 출력 1**

```
8
```

**예제 입력 2**

```
10
```

**예제 출력 2**

```
6
```

<details>
<summary>💡 힌트 보기</summary>

카드를 0부터 D−1까지의 번호 리스트로 만들고, 셔플을 실제로 반복하면서 원래 리스트와 같아지는지 확인하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
d = int(input())
origin = list(range(d))
deck = origin[:]
count = 0
while True:
    top, bottom = deck[:d // 2], deck[d // 2:]
    deck = [card for pair in zip(top, bottom) for card in pair]
    count += 1
    if deck == origin:
        break
print(count)
```

`[card for pair in zip(top, bottom) for card in pair]`는 두 절반을 지퍼처럼 엮는 이중 컴프리헨션입니다. 수학적으로는 i번째 자리의 카드가 2i mod (D−1) 자리로 옮겨 가므로, 답은 2ᵏ ≡ 1 (mod D−1)을 만족하는 가장 작은 k(2의 **위수**)입니다. 52장이면 2⁸ = 256 = 5 × 51 + 1이라 8번입니다. 그래서 D = 64(63 = 2⁶ − 1)는 6번이면 되지만, 비슷한 크기라도 998처럼 D−1이 큰 소수인 경우에는 훨씬 오래 걸립니다. 시뮬레이션이 수학적 구조를 드러내는 좋은 예입니다.

</details>
