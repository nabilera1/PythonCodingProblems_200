## 086. 안전한 나눗셈

실제 세상의 입력은 늘 깨끗하지 않습니다. 0으로 나누려 하거나, 숫자 자리에 글자를 적기도 합니다. `try`-`except`는 오류가 나도 프로그램 전체가 멈추지 않도록 그 자리에서 받아 내는 그물입니다.

**문제** 첫째 줄에 N, 이어서 N줄에 두 값 `a b`가 주어집니다. 각 줄마다 `a // b`를 출력하되, b가 0이면 `0으로 나눌 수 없음`, a나 b가 정수가 아니면 `잘못된 입력`을 출력하십시오.

**예제 입력**

```
4
7 2
-7 2
3 0
x 5
```

**예제 출력**

```
3
-4
0으로 나눌 수 없음
잘못된 입력
```

<details>
<summary>💡 힌트 보기</summary>

`int()` 변환과 나눗셈을 모두 `try` 안에 두고, `except ZeroDivisionError:`와 `except ValueError:`를 따로 쓰십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
for _ in range(n):
    a, b = input().split()
    try:
        print(int(a) // int(b))
    except ZeroDivisionError:
        print("0으로 나눌 수 없음")
    except ValueError:
        print("잘못된 입력")
```

`except` 절은 위에서부터 차례로 맞는 것을 찾습니다. `except:`처럼 종류를 적지 않으면 오타로 생긴 오류까지 삼켜 버려 버그를 숨기게 되므로, 잡을 오류를 구체적으로 적는 것이 원칙입니다. `-7 // 2`가 −3이 아니라 −4인 것에 주목하십시오. 파이썬의 `//`는 **내림**(바닥) 나눗셈이라 음수에서는 0이 아니라 음의 무한대 쪽으로 내립니다. 그래서 `a == (a // b) * b + a % b`가 언제나 성립합니다.

</details>

## 087. 숫자만 더하기

'허락보다 용서를 구하는 것이 쉽다(EAFP)'는 파이썬 공동체의 오래된 격언입니다. 미리 모든 경우를 검사하기보다 일단 해 보고 실패하면 처리하는 편이 간결할 때가 많습니다.

**문제** 공백으로 구분된 토큰들이 한 줄로 주어집니다. 그 가운데 `int()`로 정수 변환이 되는 토큰만 골라 합을 출력하십시오.

**예제 입력**

```
3 apple -2 4.5 10 +7
```

**예제 출력**

```
18
```

<details>
<summary>💡 힌트 보기</summary>

토큰마다 `try: total += int(t)` / `except ValueError: pass`.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
total = 0
for t in input().split():
    try:
        total += int(t)
    except ValueError:
        pass
print(total)
```

`int()`는 `+7`, `-0`, `007`은 받아들이지만 `4.5`나 `1e3`은 거부합니다. 실수 표기는 `float()`의 몫이기 때문입니다. `t.isdigit()`로 미리 검사하는 방법(LBYL, '뛰기 전에 살펴라')은 `-2`나 `+7`을 놓칩니다. 부호까지 정확히 검사하려면 조건이 복잡해집니다. EAFP 방식이 빛나는 경우입니다. 덤으로, `int("1_000")`이 1000이 된다는 사실도 알아 두십시오. 파이썬 3.6부터 숫자 안의 밑줄을 자릿수 구분자로 허용합니다.

</details>

## 088. match로 만든 계산기

파이썬 3.10에서 들어온 `match` 문은 값의 **모양**을 보고 갈래를 나눕니다. 단순한 값 비교에서는 `if`-`elif` 사슬보다 의도가 또렷하게 드러납니다.

**문제** 첫째 줄에 N, 이어서 N줄에 `a 연산자 b`(a, b는 정수)가 주어집니다. 연산자 `+`, `-`, `*`, `//`, `%`의 결과를 출력하십시오. `//`나 `%`에서 b가 0이면 `0으로 나눌 수 없음`, 그 밖의 연산자이면 `지원하지 않는 연산`을 출력합니다. `match` 문을 쓰십시오.

**예제 입력**

```
5
7 + 5
7 // 2
7 % 0
2 ** 10
-7 % 3
```

**예제 출력**

```
12
3
0으로 나눌 수 없음
지원하지 않는 연산
2
```

<details>
<summary>💡 힌트 보기</summary>

`match op:` 아래에 `case "+":`, `case "//" | "%" if b == 0:`, `case _:` 같은 갈래를 두십시오. `|`는 '또는', `if`는 추가 조건(가드)입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
for _ in range(n):
    a, op, b = input().split()
    a, b = int(a), int(b)
    match op:
        case "//" | "%" if b == 0:
            print("0으로 나눌 수 없음")
        case "+":
            print(a + b)
        case "-":
            print(a - b)
        case "*":
            print(a * b)
        case "//":
            print(a // b)
        case "%":
            print(a % b)
        case _:
            print("지원하지 않는 연산")
```

`case _:`는 어느 갈래에도 맞지 않을 때 실행되는 '나머지 전부'입니다. 가드(`if b == 0`)가 붙은 갈래를 맨 위에 둔 것은 0으로 나누는 경우를 먼저 걸러 내기 위해서입니다. `-7 % 3`이 2인 것은 86번에서 본 내림 나눗셈과 짝을 이루는 성질입니다. `match`는 3.10 이상에서만 동작하므로, Colab(3.12)에서는 문제없지만 오래된 환경에서는 문법 오류가 납니다.

</details>

## 089. 로봇의 명령어

`match`의 진짜 힘은 **구조 분해**에 있습니다. `case ["go", k]:`는 '두 칸짜리 리스트이고 첫 칸이 "go"이면, 둘째 칸을 k라 부르라'는 뜻입니다. 모양을 검사하는 일과 값을 꺼내는 일을 한 번에 합니다.

**문제** 로봇이 (0, 0)에서 북쪽을 보고 서 있습니다. 첫째 줄에 N, 이어서 N줄에 명령이 주어집니다. 명령은 `go k`(앞으로 k칸), `back k`(뒤로 k칸), `left`(왼쪽으로 90° 회전), `right`(오른쪽으로 90° 회전) 네 가지입니다. 북쪽은 y가 커지는 방향, 동쪽은 x가 커지는 방향입니다. 모든 명령을 수행한 뒤 `x y 방향`을 출력하십시오. 방향은 `N`, `E`, `S`, `W` 중 하나입니다.

**제한** 1 ≤ N ≤ 1000, 1 ≤ k ≤ 1000

**예제 입력**

```
5
go 3
right
go 2
left
back 1
```

**예제 출력**

```
2 2 N
```

<details>
<summary>💡 힌트 보기</summary>

방향을 0~3의 번호로 두고 `DX = [0, 1, 0, -1]`, `DY = [1, 0, -1, 0]`처럼 표를 만드십시오. 오른쪽 회전은 번호 +1, 왼쪽 회전은 −1(4로 나눈 나머지)입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
DX, DY, NAMES = [0, 1, 0, -1], [1, 0, -1, 0], "NESW"
x = y = d = 0
for _ in range(int(input())):
    match input().split():
        case ["go", k]:
            x += DX[d] * int(k); y += DY[d] * int(k)
        case ["back", k]:
            x -= DX[d] * int(k); y -= DY[d] * int(k)
        case ["left"]:
            d = (d - 1) % 4
        case ["right"]:
            d = (d + 1) % 4
print(x, y, NAMES[d])
```

방향 벡터 표 `DX`, `DY`는 격자 문제의 단골 도구입니다. 방향마다 `if`를 쓰는 대신 번호 하나로 모든 방향을 똑같이 다룰 수 있습니다. 제2부의 '시뮬레이션'과 '2차원 격자'에서 계속 쓰입니다. `case ["go", k]`는 명령이 정확히 두 단어일 때만 맞습니다. 그래서 잘못된 형식의 명령은 어느 갈래에도 걸리지 않고 조용히 무시됩니다.

</details>

## 090. 끝을 알 수 없는 입력

35번에서는 0이라는 약속된 끝 표시가 있었습니다. 그런데 끝 표시 없이 입력이 그냥 끝나 버리기도 합니다. 이때 `input()`은 `EOFError`를 일으킵니다. EOF는 End Of File, 곧 '파일의 끝'입니다.

**문제** 한 줄에 정수가 하나씩, 개수를 알 수 없게 주어집니다(적어도 하나). 입력이 끝날 때까지 읽어 **개수, 합, 최댓값**을 공백으로 구분해 출력하십시오.

**예제 입력**

```
3
-1
4
1
5
```

**예제 출력**

```
5 12 5
```

<details>
<summary>💡 힌트 보기</summary>

`while True:` 안에서 `try: x = int(input())`, `except EOFError: break`.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
nums = []
while True:
    try:
        nums.append(int(input()))
    except EOFError:
        break
print(len(nums), sum(nums), max(nums))
```

예외 처리를 흐름 제어에 쓰는 대표적인 예입니다. 다른 방법으로는 `import sys` 후 `nums = [int(line) for line in sys.stdin]`이 있습니다. `sys.stdin`은 남은 줄을 끝까지 하나씩 내놓습니다. Colab에서 `%run`으로 직접 실행해 볼 때는 입력 칸에 아무것도 넣지 않고 엔터를 치면 EOF가 아니라 빈 문자열이 들어와 `ValueError`가 납니다. 채점기는 진짜 EOF를 보내므로 걱정하지 않아도 됩니다.

</details>
