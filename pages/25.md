## 121. 좌표 압축

값의 크기는 상관없고 **순서만** 중요할 때가 있습니다. 그럴 때 10억 같은 큰 값을 0, 1, 2, …의 순위로 바꾸면 그 값을 리스트의 인덱스로 바로 쓸 수 있습니다. 이 기법을 좌표 압축이라 하며, 제3부의 세그먼트 트리 문제에서 자주 짝을 이룹니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다. 각 수를 '그 수보다 작은 **서로 다른** 값의 개수'로 바꾸어 출력하십시오.

**제한** 1 ≤ N ≤ 10⁵, |각 수| ≤ 10⁹

**예제 입력**

```
5
2 4 -10 4 -9
```

**예제 출력**

```
2 3 0 3 1
```

<details>
<summary>💡 힌트 보기</summary>

`sorted(set(a))`로 서로 다른 값을 정렬한 뒤, 값 → 순위 딕셔너리를 만드십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
a = list(map(int, input().split()))
rank = {v: i for i, v in enumerate(sorted(set(a)))}
print(*[rank[x] for x in a])
```

정렬 O(N log N) 한 번과 딕셔너리 조회 N번으로 끝납니다. 딕셔너리 대신 `bisect_left(정렬된값들, x)`로 순위를 구해도 같은 결과가 나옵니다(95번). '값 자체는 버리고 대소 관계만 남긴다'는 생각은 문제의 본질을 드러내는 **추상화**입니다.

</details>

## 122. 거품 정렬의 교환 횟수

거품 정렬은 이웃한 두 원소의 순서가 틀렸으면 바꾸는 일을 반복합니다. 큰 값이 거품처럼 위로 떠오른다고 해서 붙은 이름입니다. 느리기로 유명하지만, 교환 횟수 속에는 뜻밖의 의미가 숨어 있습니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다. 거품 정렬로 오름차순 정렬할 때 이웃한 두 원소를 **교환하는 횟수**를 출력하십시오(같은 값은 교환하지 않습니다).

**제한** 1 ≤ N ≤ 1000, |각 수| ≤ 10⁹

**예제 입력**

```
5
3 1 2 5 4
```

**예제 출력**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

거품 정렬을 그대로 구현해 교환할 때마다 세어도 되고, '앞에 있는데 더 큰' 쌍 (i < j, a[i] > a[j])의 개수를 세어도 됩니다. 두 값은 언제나 같습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
a = list(map(int, input().split()))
print(sum(1 for i in range(n) for j in range(i + 1, n) if a[i] > a[j]))
```

이웃한 두 원소를 바꾸면 순서가 뒤바뀐 쌍(**역순쌍, inversion**)이 정확히 하나 줄어듭니다. 거품 정렬은 역순쌍이 0이 될 때까지 교환하므로, 교환 횟수가 곧 역순쌍의 개수입니다. 역순쌍은 두 순위가 얼마나 다른지를 재는 척도로도 쓰입니다(켄달의 타우, 1938). N이 10⁵을 넘으면 O(N²)으로는 안 되고, 병합 정렬이나 펜윅 트리로 O(N log N)에 세야 합니다. 제3부 193번에서 다룹니다.

</details>

## 123. 가장 가까운 두 수

정렬은 '가까운 것끼리 이웃하게' 만듭니다. 그래서 가장 가까운 두 값을 찾는 문제는 정렬하는 순간 거의 다 풀립니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다. 서로 다른 위치의 두 수의 차이 가운데 가장 작은 값을 출력하십시오.

**제한** 2 ≤ N ≤ 10⁵, |각 수| ≤ 10⁹

**예제 입력**

```
5
10 3 7 21 8
```

**예제 출력**

```
1
```

<details>
<summary>💡 힌트 보기</summary>

정렬한 뒤 이웃한 원소끼리의 차이만 보면 됩니다. 이웃하지 않은 두 원소의 차이는 그 사이의 어떤 이웃 차이보다 작을 수 없기 때문입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
a = sorted(map(int, input().split()))
print(min(y - x for x, y in zip(a, a[1:])))
```

모든 쌍을 비교하면 약 50억 번이지만, 정렬 뒤 이웃만 비교하면 N − 1번입니다. `zip(a, a[1:])`은 이웃한 쌍 (a[0], a[1]), (a[1], a[2]), …를 만드는 관용구이며, 3.10부터는 `itertools.pairwise(a)`도 있습니다. 2차원 평면에서 가장 가까운 두 점을 찾는 문제는 이렇게 간단하지 않습니다. 분할 정복으로 O(N log N)에 푸는 알고리즘은 1975년 샤모스와 호이가 발표했습니다.

</details>

## 124. H-지수

2005년 물리학자 호르헤 허시는 연구자의 업적을 숫자 하나로 나타내는 지표를 제안했습니다. 'h편 이상의 논문이 각각 h번 이상 인용되었다'를 만족하는 가장 큰 h입니다. 많이 쓰기만 해서도, 한 편만 대박이 나서도 높아지지 않는 지표입니다.

**문제** 첫째 줄에 논문 수 N, 둘째 줄에 각 논문의 인용 횟수가 주어질 때 H-지수를 출력하십시오.

**제한** 1 ≤ N ≤ 10⁵, 0 ≤ 인용 횟수 ≤ 10⁹

**예제 입력 1**

```
5
3 0 6 1 5
```

**예제 출력 1**

```
3
```

**예제 입력 2**

```
3
100 100 100
```

**예제 출력 2**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

내림차순으로 정렬하면, i번째(1부터) 논문의 인용 횟수가 i 이상인 마지막 i가 답입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
c = sorted(map(int, input().split()), reverse=True)
h = 0
for i, x in enumerate(c, 1):
    if x >= i:
        h = i
    else:
        break
print(h)
```

내림차순으로 정렬하면 '상위 i편이 모두 i번 이상 인용되었는가'는 i번째 논문만 보면 알 수 있습니다. 나머지는 모두 그보다 많이 인용되었기 때문입니다. 정렬 없이 O(N)에 푸는 방법도 있습니다. 답은 N을 넘을 수 없으므로 인용 횟수를 N에서 잘라 계수 정렬하듯 세는 것입니다. 생각해 보십시오.

</details>

## 125. 가장 큰 수 만들기

정렬의 기준을 직접 정의할 수 있다면 놀라운 일들이 가능해집니다. 3과 30 중 무엇을 앞에 둘까요? 숫자 크기로는 30이 크지만, 이어 붙여 보면 330이 303보다 큽니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 0 이상 정수가 주어집니다. 모든 수를 한 번씩 이어 붙여 만들 수 있는 가장 큰 수를 출력하십시오.

**제한** 1 ≤ N ≤ 1000, 0 ≤ 각 수 ≤ 10⁹

**예제 입력 1**

```
5
3 30 34 5 9
```

**예제 출력 1**

```
9534330
```

**예제 입력 2**

```
3
0 0 0
```

**예제 출력 2**

```
0
```

<details>
<summary>💡 힌트 보기</summary>

두 문자열 x, y에 대해 `x + y > y + x`이면 x를 앞에 두어야 합니다. `functools.cmp_to_key`로 이 비교 함수를 정렬 기준으로 바꿀 수 있습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from functools import cmp_to_key
n = int(input())
nums = input().split()

def cmp(x, y):
    if x + y > y + x:
        return -1
    if x + y < y + x:
        return 1
    return 0

nums.sort(key=cmp_to_key(cmp))
print(str(int("".join(nums))))
```

이 비교 규칙이 정렬에 쓰여도 괜찮은지(추이성이 성립하는지)는 자명하지 않지만, x + y > y + x라는 관계가 추이적임이 증명되어 있습니다. 정렬 기준을 직접 만들 때는 늘 이 점을 따져야 합니다. `0 0 0`을 이어 붙이면 `000`이 되므로 `int()`로 한 번 바꾸어 앞의 0을 없앴습니다. 파이썬 3의 `sort`는 비교 함수를 직접 받지 않고 `key`만 받습니다. 그래서 옛 방식의 비교 함수는 `cmp_to_key`로 감싸야 합니다.

</details>
