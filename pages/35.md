## 171. 계단 오르기

동적 계획법(Dynamic Programming)이라는 이름은 1950년대 리처드 벨먼이 지었습니다. 그는 훗날 '연구비를 주는 사람들이 싫어하지 않을 멋진 이름'을 골랐다고 회고했습니다. 이름과 달리 본질은 소박합니다. **작은 문제의 답을 표에 적어 두고 큰 문제에서 꺼내 쓰는 것**입니다.

**문제** 한 번에 계단을 1칸, 2칸 또는 3칸 오를 수 있을 때 n칸을 오르는 방법의 수를 1,000,000,007로 나눈 나머지로 구하십시오.

**입력** 첫째 줄에 n이 주어집니다.

**출력** 방법의 수를 출력합니다.

**제한** 1 ≤ n ≤ 10⁶, 시간 제한 2초

**예제 입력 1**

```
4
```

**예제 출력 1**

```
7
```

**예제 입력 2**

```
1
```

**예제 출력 2**

```
1
```

<details>
<summary>💡 힌트 보기</summary>

마지막 한 걸음이 1칸, 2칸, 3칸인 경우로 나누면 D[n] = D[n−1] + D[n−2] + D[n−3]입니다. D[0] = 1(아무것도 안 하는 한 가지)로 두십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
MOD = 1_000_000_007
n = int(input())
a, b, c = 0, 0, 1
for _ in range(n):
    a, b, c = b, c, (a + b + c) % MOD
print(c)
```

D[0] = 1, D[−1] = D[−2] = 0으로 두면 점화식이 n = 1, 2, 3에서도 예외 없이 맞습니다. 그래서 a, b, c를 (0, 0, 1)로 시작했습니다. 경계를 '가짜 칸'으로 처리하는 요령입니다. 필요한 것은 직전 세 값뿐이므로 길이 n의 표 대신 변수 세 개만 썼습니다. 메모리 O(1)입니다. 4칸을 오르는 7가지는 1111, 112, 121, 211, 22, 13, 31입니다. 완전 탐색 검증용 풀이는 메모 없는 재귀로, 77번에서 본 지수적 폭발 때문에 n이 30만 되어도 끝나지 않습니다.

</details>

## 172. 최대 부분 배열

1977년 울프 그레난더가 제기한 이 문제에 대해, 통계학자 조셉 케데인은 카네기 멜런 대학교의 한 세미나에서 1분도 안 되어 선형 시간 풀이를 내놓았다고 전해집니다(존 벤틀리의 『생각하는 프로그래밍』). 비결은 '여기서 끝나는 최대 구간 합'만 들고 다니는 것입니다.

**문제** 정수 N개로 된 수열에서 연속 구간(비어 있지 않음)의 합 가운데 최댓값을 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다.

**출력** 최대 구간 합을 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, |aᵢ| ≤ 10⁹, 시간 제한 2초

**예제 입력 1**

```
9
-2 1 -3 4 -1 2 1 -5 4
```

**예제 출력 1**

```
6
```

**예제 입력 2**

```
3
-5 -2 -9
```

**예제 출력 2**

```
-2
```

<details>
<summary>💡 힌트 보기</summary>

cur = 'i번째 원소에서 끝나는 구간의 최대 합'이라 하면 cur = max(aᵢ, cur + aᵢ)입니다. 앞의 구간이 손해라면 버리고 새로 시작하는 것입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
n = int(input())
best = cur = -10**19
for x in map(int, input().split()):
    cur = x if cur < 0 else cur + x
    if cur > best:
        best = cur
print(best)
```

cur가 음수이면 이어 붙여 봐야 손해이므로 새로 시작합니다. 이 판단이 `cur = x if cur < 0 else cur + x` 한 줄입니다. 모든 원소가 음수일 때 답을 0으로 내는 실수가 흔합니다. 문제는 **비어 있지 않은** 구간을 요구하므로, 예제 2처럼 가장 큰 음수 하나가 답입니다. 초깃값을 충분히 작은 수로 둔 이유입니다. 이 알고리즘은 '어디서 끝나는가'로 상태를 정의하는 동적 계획법의 전형입니다.

</details>

## 173. 가장 긴 증가 부분 수열

수열에서 몇 개를 골라 순서를 유지한 채 늘어놓았을 때 엄격하게 증가하는 가장 긴 것을 찾는 문제입니다. O(N²) 동적 계획법은 잘 알려져 있지만, N이 20만이면 너무 느립니다. 1975년 프레드먼이 분석한 O(N log N) 방법은 '길이별로 끝값을 가장 작게 유지하는' 영리한 표를 씁니다.

**문제** 길이 N의 수열에서 가장 긴 **엄격하게** 증가하는 부분 수열의 길이를 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다.

**출력** 길이를 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, |aᵢ| ≤ 10⁹, 시간 제한 2초

**예제 입력 1**

```
8
10 9 2 5 3 7 101 18
```

**예제 출력 1**

```
4
```

**예제 입력 2**

```
4
7 7 7 7
```

**예제 출력 2**

```
1
```

<details>
<summary>💡 힌트 보기</summary>

tails[k] = '길이 k+1인 증가 부분 수열들의 끝값 가운데 최솟값'이라 하면 tails는 정렬되어 있습니다. 새 원소 x마다 `bisect_left(tails, x)` 자리를 x로 바꾸거나 맨 뒤에 붙이십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
from bisect import bisect_left
input = sys.stdin.readline
n = int(input())
tails = []
for x in map(int, input().split()):
    i = bisect_left(tails, x)
    if i == len(tails):
        tails.append(x)
    else:
        tails[i] = x
print(len(tails))
```

끝값이 작을수록 뒤에 더 많은 수를 이어 붙일 수 있으므로, 같은 길이라면 끝값이 작은 것만 기억하면 됩니다. tails는 길이별 '가장 유망한 끝값'의 표입니다. 엄격한 증가이므로 `bisect_left`를 씁니다. 같은 값이 들어오면 기존 값을 대체할 뿐 길이를 늘리지 않습니다. '감소하지 않는' 부분 수열이라면 `bisect_right`로 바꾸면 됩니다. 예제 2가 그 차이를 시험합니다. 주의할 점: tails 자체는 실제 부분 수열이 아닙니다. 수열을 복원하려면 각 원소가 들어간 위치와 이전 원소를 따로 기록해야 합니다.

</details>

## 174. 배낭 문제

무게 제한이 있는 배낭에 가치가 최대가 되도록 물건을 담는 0-1 배낭 문제는 NP-완전이지만, 무게가 작은 정수라면 '무게 w까지 썼을 때의 최대 가치' 표로 효율적으로 풀 수 있습니다. 무게 크기에 비례하는 이런 시간을 '의사 다항 시간'이라 부릅니다.

**문제** N개의 물건이 (무게, 가치)로 주어지고 배낭의 최대 무게가 W입니다. 각 물건을 넣거나 넣지 않을 때, 무게 합이 W 이하가 되도록 하는 가치 합의 최댓값을 구하십시오.

**입력** 첫째 줄에 N과 W, 이어서 N줄에 무게와 가치가 주어집니다.

**출력** 최대 가치를 출력합니다.

**제한** 1 ≤ N ≤ 100, 1 ≤ W ≤ 10⁵, 1 ≤ 무게 ≤ 10⁵, 0 ≤ 가치 ≤ 10⁹, 시간 제한 3초

**예제 입력**

```
4 7
6 13
4 8
3 6
5 12
```

**예제 출력**

```
14
```

<details>
<summary>💡 힌트 보기</summary>

best[w] = 무게 합 w 이하에서의 최대 가치. 물건 (wi, vi)마다 w를 **큰 쪽에서 작은 쪽으로** 내려가며 best[w] = max(best[w], best[w − wi] + vi)로 갱신하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
n, W = map(int, input().split())
best = [0] * (W + 1)
for _ in range(n):
    wi, vi = map(int, input().split())
    if wi > W:
        continue
    shifted = [b + vi for b in best[:W + 1 - wi]]
    best[wi:] = map(max, best[wi:], shifted)
print(best[W])
```

1차원 표에서 w를 큰 쪽부터 갱신하는 이유는 같은 물건을 두 번 넣지 않기 위해서입니다. 작은 쪽부터 갱신하면 방금 갱신한 값을 다시 써서 같은 물건이 여러 번 들어갑니다. 그것은 '무한히 넣을 수 있는' 배낭(176번)의 풀이가 됩니다. 모범답안은 이 '큰 쪽부터'를 다른 방식으로 구현했습니다. 갱신 전의 표(`best[:W+1-wi]`)를 통째로 복사해 두고 `map(max, …)`로 한꺼번에 비교하는 것입니다. 파이썬 반복문 대신 내장 함수로 처리하므로 N × W = 10⁷회 연산이 몇 배 빨라집니다. 파이썬에서 동적 계획법이 느릴 때는 **가장 안쪽 반복문을 내장 함수나 슬라이스 연산으로 바꾸는 것**이 가장 효과적인 최적화입니다.

</details>

## 175. 최장 공통 부분 수열

유닉스의 `diff` 명령은 두 파일에서 바뀌지 않은 줄들, 곧 최장 공통 부분 수열을 찾아 그 밖의 줄을 변경 사항으로 보여 줍니다. 1976년 헌트와 매킬로이가 만든 이 도구의 후손들이 오늘날 깃(git)의 변경 비교 기능에도 쓰입니다.

**문제** 두 문자열 A, B가 주어질 때 둘 모두의 부분 수열(순서를 유지하며 일부를 고른 것)인 문자열 가운데 가장 긴 것의 길이를 구하십시오.

**입력** 첫째 줄에 A, 둘째 줄에 B가 주어집니다.

**출력** 최장 공통 부분 수열의 길이를 출력합니다.

**제한** 1 ≤ |A|, |B| ≤ 2000, 영어 대문자, 시간 제한 4초

**예제 입력**

```
ACAYKP
CAPCAK
```

**예제 출력**

```
4
```

<details>
<summary>💡 힌트 보기</summary>

L[i][j] = A의 앞 i글자와 B의 앞 j글자의 LCS 길이. 마지막 글자가 같으면 L[i−1][j−1] + 1, 다르면 max(L[i−1][j], L[i][j−1])입니다. 147번 편집 거리와 같은 모양의 표입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
a, b = input(), input()
m = len(b)
prev = [0] * (m + 1)
for ch in a:
    cur = [0] * (m + 1)
    for j in range(m):
        if ch == b[j]:
            cur[j + 1] = prev[j] + 1
        else:
            cur[j + 1] = cur[j] if cur[j] > prev[j + 1] else prev[j + 1]
    prev = cur
print(prev[m])
```

예제의 LCS는 ACAK(또는 CAPK 등)로 길이 4입니다. LCS는 여러 개일 수 있지만 **길이**는 하나뿐이므로 답이 하나로 정해집니다. 좋은 문제는 이런 식으로 답의 유일성을 보장합니다. 2000 × 2000 = 400만 칸입니다. 파이썬에서는 표 접근을 최소화하는 것이 중요합니다. `max()` 함수 호출 대신 조건 표현식을 쓰고, 행 두 개만 유지하여 시간을 줄였습니다. 완전 탐색 검증용 풀이의 `ch in it`은 이터레이터를 앞으로 소비하며 찾는 관용구로, '부분 수열인가'를 한 줄로 판정합니다.

</details>
