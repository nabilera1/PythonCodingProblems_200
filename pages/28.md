## 136. N-퀸

1848년 체스 문제 작가 막스 베첼이 '서로 공격하지 않도록 8개의 퀸을 체스판에 놓는 방법'을 물었고, 가우스도 이 문제에 관심을 보였습니다. 답은 92가지이며, 1972년 다익스트라는 이 문제를 구조적 프로그래밍과 백트래킹의 교재로 삼았습니다.

**문제** N×N 체스판에 퀸 N개를 서로 공격할 수 없게(같은 행, 열, 대각선에 두 개가 없게) 놓는 방법의 수를 출력하십시오.

**제한** 1 ≤ N ≤ 10

**예제 입력 1**

```
4
```

**예제 출력 1**

```
2
```

**예제 입력 2**

```
8
```

**예제 출력 2**

```
92
```

<details>
<summary>💡 힌트 보기</summary>

한 행에 퀸은 정확히 하나이므로 행마다 열 하나를 고르면 됩니다. 이미 쓴 열, 이미 쓴 ↘ 대각선(r − c), ↙ 대각선(r + c)을 집합으로 기억해 두고, 겹치는 칸은 건너뛰십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
def place(r):
    if r == n:
        return 1
    total = 0
    for c in range(n):
        if c in cols or r - c in d1 or r + c in d2:
            continue
        cols.add(c); d1.add(r - c); d2.add(r + c)
        total += place(r + 1)
        cols.remove(c); d1.remove(r - c); d2.remove(r + c)
    return total

n = int(input())
cols, d1, d2 = set(), set(), set()
print(place(0))
```

같은 ↘ 대각선 위의 칸들은 r − c가 같고, 같은 ↙ 대각선 위의 칸들은 r + c가 같습니다. 이 관찰 덕분에 대각선 검사가 집합 조회 한 번으로 줄어듭니다. 막힌 갈래를 일찍 잘라 내는 **가지치기**가 백트래킹의 효율을 좌우합니다. 8×8에서 아무렇게나 놓는 방법은 약 44억 가지이지만, 이 프로그램은 2천 번 남짓의 시도로 92가지를 찾아냅니다.

</details>

## 137. 부분집합의 합

주어진 수들 가운데 몇 개를 골라 정확히 S를 만드는 문제는 겉보기에 단순하지만, 수가 많아지면 효율적으로 풀 수 있는 방법이 알려지지 않은 'NP-완전' 문제입니다. 크기가 작을 때는 모든 부분집합을 차례로 살펴보는 것이 정직한 방법입니다.

**문제** 첫째 줄에 N과 S, 둘째 줄에 N개의 정수가 주어집니다. 공집합이 아닌 부분집합 가운데 원소의 합이 S인 것의 개수를 출력하십시오. (같은 값이라도 위치가 다르면 다른 원소입니다.)

**제한** 1 ≤ N ≤ 18, |S| ≤ 10⁶, |각 수| ≤ 10⁵

**예제 입력 1**

```
5 0
-7 -3 -2 5 8
```

**예제 출력 1**

```
1
```

**예제 입력 2**

```
3 2
1 1 1
```

**예제 출력 2**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

재귀 함수 `go(i, s)`: i번째 원소를 넣는 경우와 넣지 않는 경우로 나누어 진행합니다. i = N에 이르렀을 때 합이 S이면 하나로 셉니다. S = 0이면 공집합을 빼는 것을 잊지 마십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
def go(i, s):
    if i == n:
        return 1 if s == target else 0
    return go(i + 1, s + a[i]) + go(i + 1, s)

n, target = map(int, input().split())
a = list(map(int, input().split()))
print(go(0, 0) - (1 if target == 0 else 0))
```

모든 원소마다 '넣는다/안 넣는다' 두 갈래가 있으므로 부분집합은 2ᴺ개입니다. N = 18이면 약 26만 개로 충분히 살펴볼 수 있지만, N = 40이면 1조 개가 넘습니다. 그럴 때는 수를 두 무리로 나누어 각각의 부분합을 모두 구한 뒤 짝을 맞추는 **중간에서 만나기**(meet in the middle) 기법으로 2^(N/2) 수준까지 줄일 수 있습니다. 공집합의 합은 0이므로 S = 0일 때 공집합이 한 번 세어집니다. 그래서 마지막에 1을 뺐습니다.

</details>

## 138. 조합 만들기

80번에서 순열을 만들었다면, 이번에는 순서가 상관없는 조합입니다. 앞에서 고른 수보다 **큰 수만** 고르도록 제한하면, 같은 조합이 순서만 바꾸어 다시 나오는 일이 자연스럽게 사라집니다.

**문제** N과 M이 주어질 때 1부터 N까지의 수 가운데 M개를 고르는 모든 조합을 오름차순으로 나열하여, 사전 순서로 한 줄에 하나씩 출력하십시오.

**제한** 1 ≤ M ≤ N ≤ 12

**예제 입력**

```
4 2
```

**예제 출력**

```
1 2
1 3
1 4
2 3
2 4
3 4
```

<details>
<summary>💡 힌트 보기</summary>

재귀 함수 `go(start)`: 현재 조합의 길이가 M이면 기록하고, 아니면 start부터 N까지의 수를 하나씩 넣어 `go(그 수 + 1)`을 부르십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
def go(start):
    if len(comb) == m:
        out.append(" ".join(map(str, comb)))
        return
    for x in range(start, n + 1):
        comb.append(x)
        go(x + 1)
        comb.pop()

n, m = map(int, input().split())
comb, out = [], []
go(1)
print("\n".join(out))
```

80번의 순열과 다른 점은 `used` 배열 대신 `start` 인자를 둔 것 하나뿐입니다. 이 작은 차이가 '순서가 있는 선택'과 '순서가 없는 선택'을 가릅니다. 남은 수가 모자라 M개를 채울 수 없는 갈래(예: x > N − (M − len(comb)) + 1)를 미리 잘라 내면 더 빨라집니다. 실전에서는 `itertools.combinations(range(1, n + 1), m)`이 같은 순서로 조합을 만들어 줍니다.

</details>

## 139. 괄호의 카탈랑 수

올바른 괄호열의 개수 1, 1, 2, 5, 14, 42, …는 19세기 벨기에의 수학자 카탈랑의 이름을 딴 수열입니다. 이 수열은 다각형을 삼각형으로 나누는 방법의 수, 이진 트리의 모양의 수 등 놀랄 만큼 많은 곳에서 나타납니다.

**문제** n이 주어질 때 괄호 n쌍으로 만들 수 있는 올바른 괄호열을 모두 사전 순서(`(`가 `)`보다 앞)로 한 줄에 하나씩 출력하십시오.

**제한** 1 ≤ n ≤ 8

**예제 입력**

```
3
```

**예제 출력**

```
((()))
(()())
(())()
()(())
()()()
```

<details>
<summary>💡 힌트 보기</summary>

지금까지 쓴 여는 괄호 수 `open`과 닫는 괄호 수 `close`를 들고 다니십시오. `open < n`이면 `(`를, `close < open`이면 `)`를 붙일 수 있습니다. 앞의 것을 먼저 시도하면 사전 순서가 됩니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
def go(s, open_, close):
    if len(s) == 2 * n:
        out.append(s)
        return
    if open_ < n:
        go(s + "(", open_ + 1, close)
    if close < open_:
        go(s + ")", open_, close + 1)

n = int(input())
out = []
go("", 0, 0)
print("\n".join(out))
```

`close < open` 조건 하나가 '닫는 괄호가 여는 괄호보다 많아지는 순간'을 원천적으로 막아 줍니다. 그래서 만들어지는 모든 문자열이 올바르며, 131번 같은 검사를 따로 할 필요가 없습니다. 틀린 후보를 만들고 거르는 대신 **처음부터 옳은 것만 만드는** 것이 좋은 백트래킹입니다. n = 8이면 카탈랑 수 C₈ = 1430개가 나옵니다. 일반항은 C(2n, n) / (n + 1)입니다.

</details>

## 140. 연산자 끼워 넣기

수 사이에 연산자를 끼워 넣는 퍼즐은 백트래킹의 단골 소재입니다. 이 문제에는 숨은 함정이 하나 있습니다. 나눗셈을 C 언어처럼 0 쪽으로 버리는지, 파이썬처럼 음의 무한대 쪽으로 내리는지입니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 수, 셋째 줄에 덧셈·뺄셈·곱셈·나눗셈 연산자의 개수(합은 N−1)가 주어집니다. 수의 순서는 그대로 두고 수 사이에 연산자를 모두 하나씩 끼워 넣어, 우선순위 없이 **왼쪽부터 차례로** 계산합니다. 나눗셈은 정수 나눗셈이며 **몫의 소수점 아래를 0 쪽으로 버립니다**(예: −7 ÷ 2 = −3). 만들 수 있는 결과의 최댓값과 최솟값을 한 줄에 하나씩 출력하십시오.

**제한** 2 ≤ N ≤ 11, 1 ≤ 각 수 ≤ 100, 중간 결과의 절댓값은 10⁹ 이하

**예제 입력 1**

```
3
3 4 5
1 0 1 0
```

**예제 출력 1**

```
35
17
```

**예제 입력 2**

```
3
1 2 7
0 1 0 1
```

**예제 출력 2**

```
0
-7
```

<details>
<summary>💡 힌트 보기</summary>

남은 연산자 개수를 리스트로 들고 다니며, 개수가 남아 있는 연산자마다 하나씩 써 보고 재귀한 뒤 되돌리십시오. 0 쪽으로 버리는 나눗셈은 `int(a / b)`가 아니라 부호를 따로 처리해 정수만으로 계산하는 것이 안전합니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
def div(a, b):
    q = abs(a) // abs(b)
    return q if (a >= 0) == (b > 0) else -q

def go(i, value):
    global best, worst
    if i == n:
        best, worst = max(best, value), min(worst, value)
        return
    for k in range(4):
        if ops[k]:
            ops[k] -= 1
            x = a[i]
            go(i + 1, value + x if k == 0 else value - x if k == 1 else value * x if k == 2 else div(value, x))
            ops[k] += 1

n = int(input())
a = list(map(int, input().split()))
ops = list(map(int, input().split()))
best, worst = -10**18, 10**18
go(1, a[0])
print(best)
print(worst)
```

예제 2에서 1 − 2 = −1, −1 ÷ 7은 0 쪽으로 버리면 0이지만 파이썬의 `//`로는 −1이 되어, 최댓값을 0이 아닌 −1로 잘못 답하게 됩니다. 문제의 약속을 언어의 기본 동작과 혼동하지 않는 것이 이 문제의 진짜 시험입니다. `int(a / b)`도 대개 맞지만, 실수 나눗셈을 거치므로 값이 아주 크면 오차가 생길 수 있습니다. 정수만으로 계산하는 `div` 함수가 더 안전합니다. 연산자의 배치는 최대 10! / (각 개수!의 곱)가지라 많아야 수십만 가지입니다. 함수 안에서 바깥 변수를 바꾸기 위해 `global`을 썼습니다.

</details>
