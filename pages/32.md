## 156. 회의실 하나

회의실이 하나뿐일 때 겹치지 않게 최대한 많은 회의를 배정하려면 어떤 회의부터 골라야 할까요? 짧은 회의? 일찍 시작하는 회의? 정답은 **가장 일찍 끝나는 회의**입니다. 그래야 남은 시간이 가장 많이 남기 때문입니다.

**문제** N개의 회의가 [시작, 끝) 시간으로 주어집니다. 한 회의가 끝나는 시각에 다음 회의가 시작할 수 있습니다. 서로 겹치지 않게 고를 수 있는 회의의 최대 개수를 구하십시오.

**입력** 첫째 줄에 N, 이어서 N줄에 시작 시각과 끝 시각이 주어집니다.

**출력** 최대 회의 수를 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, 0 ≤ 시작 < 끝 ≤ 10⁹, 시간 제한 2초

**예제 입력**

```
6
1 4
3 5
0 6
5 7
3 9
7 10
```

**예제 출력**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

끝나는 시각 순으로 정렬한 뒤, 마지막으로 고른 회의가 끝난 뒤에 시작하는 회의를 차례로 고르십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
data = sys.stdin.buffer.read().split()
n = int(data[0])
meetings = sorted(zip(map(int, data[2::2]), map(int, data[1::2])))
count, end = 0, -1
for e, s in meetings:
    if s >= end:
        count += 1
        end = e
print(count)
```

**교환 논증**으로 증명합니다. 최적해의 첫 회의를 '가장 일찍 끝나는 회의'로 바꾸어도 뒤의 회의들과 겹치지 않으므로 개수는 그대로입니다. 이 논리를 반복하면 탐욕 선택이 최적임을 알 수 있습니다. 그리디는 증명 없이 쓰면 위험합니다. '짧은 회의 먼저'는 [1,10), [2,3) 같은 반례는 피하지만, [0,5), [4,6), [5,10)에서는 가장 짧은 [4,6)을 먼저 고르는 바람에 나머지 둘과 모두 겹쳐, 최적해 2개 대신 1개만 고르게 됩니다. 증명 없는 직관을 경계하십시오.

</details>

## 157. 필요한 회의실 수

이번에는 모든 회의를 열어야 합니다. 회의실이 최소 몇 개 있어야 할까요? 답은 '동시에 진행되는 회의 수의 최댓값'입니다. 시간축을 따라 시작은 +1, 끝은 −1로 훑는 **스위핑**이 이를 정확히 셉니다.

**문제** N개의 회의가 [시작, 끝)으로 주어질 때 모든 회의를 열기 위해 필요한 회의실의 최소 개수를 구하십시오. 끝나는 시각에 같은 회의실에서 다음 회의를 시작할 수 있습니다.

**입력** 첫째 줄에 N, 이어서 N줄에 시작 시각과 끝 시각이 주어집니다.

**출력** 필요한 회의실 수를 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, 0 ≤ 시작 < 끝 ≤ 10⁹, 시간 제한 2초

**예제 입력**

```
4
1 4
2 5
4 6
5 7
```

**예제 출력**

```
2
```

<details>
<summary>💡 힌트 보기</summary>

(시각, +1)과 (시각, −1) 사건을 모두 모아 정렬하십시오. 같은 시각이면 −1(끝)이 먼저 오도록 하면 '끝나는 시각에 시작 가능' 조건이 지켜집니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
data = sys.stdin.buffer.read().split()
n = int(data[0])
events = []
for i in range(n):
    events.append((int(data[1 + 2 * i]), 1))
    events.append((int(data[2 + 2 * i]), -1))
events.sort()
cur = best = 0
for _, d in events:
    cur += d
    best = max(best, cur)
print(best)
```

튜플 정렬에서 같은 시각이면 −1이 +1보다 작으므로 저절로 끝 사건이 먼저 처리됩니다. 부호를 고르는 것만으로 동점 규칙을 해결한 셈입니다. 다른 풀이로, 시작 시각 순으로 회의를 보며 '사용 중인 회의실의 끝나는 시각'을 최소 힙에 넣는 방법도 있습니다. 힙의 최솟값이 현재 시작 시각 이하이면 그 회의실을 재사용합니다. 두 방법 모두 O(N log N)입니다.

</details>

## 158. 보급소

일직선 길 위의 도시들을 차례로 지나 마지막 도시까지 가야 합니다. 도시마다 연료 값이 다르고, 연료 탱크는 무한히 큽니다. 비싼 곳에서는 필요한 만큼만, 싼 곳에서는 넉넉히 사 두는 것이 지혜입니다.

**문제** N개의 도시가 일직선 위에 있고, 이웃한 도시 사이의 거리와 각 도시의 1km당 연료 가격이 주어집니다. 첫 도시에서 빈 탱크로 출발해 마지막 도시에 도착하는 데 드는 최소 비용을 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N−1개의 거리, 셋째 줄에 N개의 가격이 주어집니다.

**출력** 최소 비용을 출력합니다.

**제한** 2 ≤ N ≤ 2×10⁵, 1 ≤ 거리, 가격 ≤ 10⁹, 시간 제한 2초

**예제 입력**

```
4
2 3 1
5 2 4 1
```

**예제 출력**

```
18
```

<details>
<summary>💡 힌트 보기</summary>

지금까지 지나온 도시 가운데 가장 싼 가격으로 다음 구간의 연료를 샀다고 생각하십시오. 그 가격을 들고 다니며 갱신하면 됩니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
n = int(input())
dist = list(map(int, input().split()))
price = list(map(int, input().split()))
cheapest = price[0]
cost = 0
for i in range(n - 1):
    cheapest = min(cheapest, price[i])
    cost += cheapest * dist[i]
print(cost)
```

i번째 구간을 지날 연료는 0~i번 도시 가운데 어디서든 사 둘 수 있었으므로, 그중 가장 싼 가격을 쓰는 것이 최적입니다. 구간마다 독립적으로 최선을 고를 수 있다는 점이 그리디를 정당화합니다. 답은 최대 약 2×10⁵ × 10⁹ × 10⁹ = 2×10²³으로 64비트 정수를 넘습니다. 다른 언어였다면 큰 수 처리가 필요했을 문제입니다. 완전 탐색 검증용 풀이는 'j번 도시에서 i번 도시까지 갈 연료를 한 번에 산다'는 O(N²) 동적 계획법입니다.

</details>

## 159. 마감과 보상

과제마다 마감일과 보상이 있고, 하루에 과제 하나만 끝낼 수 있습니다. 보상이 큰 과제를 먼저 하고 싶지만 마감이 먼 과제를 서두를 필요는 없습니다. **우선순위 큐**(힙)는 이런 '지금까지 고른 것 가운데 가장 못한 것을 버리는' 결정을 빠르게 해 줍니다.

**문제** N개의 과제가 (마감일 d, 보상 w)로 주어집니다. 1일째부터 하루에 한 과제씩 할 수 있고, 과제는 마감일 당일까지 끝내야 보상을 받습니다. 받을 수 있는 보상 합의 최댓값을 구하십시오.

**입력** 첫째 줄에 N, 이어서 N줄에 d와 w가 주어집니다.

**출력** 최대 보상 합을 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, 1 ≤ d ≤ 10⁹, 1 ≤ w ≤ 10⁹, 시간 제한 2초

**예제 입력**

```
5
2 50
1 10
2 20
1 30
3 5
```

**예제 출력**

```
85
```

<details>
<summary>💡 힌트 보기</summary>

마감일 순으로 과제를 보며 일단 힙에 보상을 넣습니다. 고른 과제 수가 현재 마감일보다 많아지면 힙에서 가장 작은 보상을 빼십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys, heapq
data = sys.stdin.buffer.read().split()
n = int(data[0])
jobs = sorted(zip(map(int, data[1::2]), map(int, data[2::2])))
heap = []
for d, w in jobs:
    heapq.heappush(heap, w)
    if len(heap) > d:
        heapq.heappop(heap)
print(sum(heap))
```

마감일이 d 이하인 과제들 가운데 최대 d개만 할 수 있습니다. 힙은 언제나 '지금까지의 마감 조건을 지키면서 보상이 가장 큰 과제들'을 유지합니다. 넘칠 때 가장 작은 보상을 버리는 것이 최선이기 때문입니다. 고른 과제들을 마감일 순으로 1일, 2일, …에 배치하면 모두 마감을 지킨다는 사실이 완전 탐색 검증용 풀이의 판정 기준이기도 합니다. `heapq`는 최소 힙입니다. 최대 힙이 필요하면 값에 −를 붙여 넣는 것이 파이썬의 관례입니다.

</details>

## 160. 덮인 길이

여러 화가가 담장의 구간을 칠했습니다. 겹쳐 칠한 곳이 많아 실제로 칠해진 길이는 각 구간 길이의 합보다 짧습니다. 구간을 시작점 순으로 정렬하면 겹치는 것끼리 이웃하게 되어 하나로 합칠 수 있습니다.

**문제** N개의 구간 [a, b)가 주어질 때 하나 이상의 구간에 덮인 부분의 총 길이를 구하십시오.

**입력** 첫째 줄에 N, 이어서 N줄에 a와 b가 주어집니다.

**출력** 덮인 길이를 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, −10⁹ ≤ a < b ≤ 10⁹, 시간 제한 2초

**예제 입력**

```
4
1 3
2 5
6 8
7 9
```

**예제 출력**

```
7
```

<details>
<summary>💡 힌트 보기</summary>

시작점 순으로 정렬한 뒤, 현재 합쳐진 구간의 끝보다 다음 구간의 시작이 크면 새 덩어리를 시작하고, 아니면 끝을 늘리십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
data = sys.stdin.buffer.read().split()
n = int(data[0])
seg = sorted(zip(map(int, data[1::2]), map(int, data[2::2])))
total = 0
cs, ce = seg[0]
for a, b in seg[1:]:
    if a > ce:
        total += ce - cs
        cs, ce = a, b
    else:
        ce = max(ce, b)
total += ce - cs
print(total)
```

`ce = max(ce, b)`의 `max`가 핵심입니다. 큰 구간 안에 작은 구간이 쏙 들어가는 경우(숨은 테스트 [1,10), [2,3))에 끝을 줄여 버리는 실수를 막습니다. [1,3)과 [3,5)처럼 맞닿은 구간은 합쳐도, 따로 세어도 길이가 같습니다. 그래서 `a > ce`와 `a >= ce` 가운데 무엇을 써도 됩니다. 이처럼 등호 하나가 결과를 바꾸는지 따져 보는 습관이 중요합니다. 마지막 덩어리를 더하는 줄을 빠뜨리지 마십시오(49번에서 본 바로 그 함정입니다).

</details>
