## 091. Counter와 최빈값

'파이썬에는 배터리가 포함되어 있다(batteries included).' 표준 라이브러리가 풍부하다는 자랑입니다. `collections.Counter`는 세는 일에 특화된 딕셔너리입니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다. 가장 많이 나온 값과 그 횟수를 출력하십시오. 그런 값이 여럿이면 **가장 작은 값**을 출력합니다.

**제한** 1 ≤ N ≤ 10⁵, |각 수| ≤ 10⁹

**예제 입력 1**

```
7
3 1 3 2 1 5 1
```

**예제 출력 1**

```
1 3
```

**예제 입력 2**

```
4
9 8 9 8
```

**예제 출력 2**

```
8 2
```

<details>
<summary>💡 힌트 보기</summary>

`Counter(리스트)`로 센 뒤, `min(c.items(), key=lambda kv: (-kv[1], kv[0]))`로 '횟수가 크고 값이 작은' 쌍을 고르십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from collections import Counter
n = int(input())
c = Counter(map(int, input().split()))
value, freq = min(c.items(), key=lambda kv: (-kv[1], kv[0]))
print(value, freq)
```

`c.most_common(1)`은 동점일 때 **먼저 나온** 값을 돌려줍니다. 그래서 '가장 작은 값' 조건을 보장하지 못합니다. 예제 2에서 `most_common`을 쓰면 9가 나옵니다. 도구를 쓸 때는 그 도구가 동점을 어떻게 처리하는지까지 확인해야 합니다. 문서를 읽는 습관이 필요한 이유입니다.

</details>

## 092. 스물하나

카드 게임 '스물하나'에서는 합이 21을 넘지 않으면서 21에 가장 가까운 사람이 이깁니다. `itertools.combinations`는 가능한 모든 조합을 차례로 내놓아 이런 탐색을 한 줄로 만들어 줍니다.

**문제** 첫째 줄에 카드 수 N과 상한 M, 둘째 줄에 N장의 카드 숫자가 주어집니다. 서로 다른 카드 3장을 골라 합이 M을 넘지 않으면서 M에 가장 가깝게 만들 때 그 합을 출력하십시오. 그런 조합은 반드시 존재합니다.

**제한** 3 ≤ N ≤ 100, 1 ≤ 카드 숫자 ≤ 10⁵, 3 ≤ M ≤ 3×10⁵

**예제 입력 1**

```
5 21
5 6 7 8 9
```

**예제 출력 1**

```
21
```

**예제 입력 2**

```
4 15
1 2 9 9
```

**예제 출력 2**

```
12
```

<details>
<summary>💡 힌트 보기</summary>

`for trio in combinations(cards, 3):`로 모든 3장 조합을 돌며 `sum(trio) <= M`인 것 가운데 최댓값을 구하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from itertools import combinations
n, m = map(int, input().split())
cards = list(map(int, input().split()))
print(max(s for t in combinations(cards, 3) if (s := sum(t)) <= m))
```

N = 100이면 조합은 C(100, 3) = 161,700가지로, 모두 살펴도 금방 끝납니다. 이처럼 **경우의 수를 먼저 계산해 보고** 완전 탐색이 가능한지 판단하는 습관이 중요합니다. 제너레이터 안에서 `:=`로 합을 한 번만 계산했습니다. 쓰기 어렵다면 평범한 이중 조건문으로 풀어도 좋습니다.

</details>

## 093. 며칠 남았을까

날짜 계산은 생각보다 까다롭습니다. 달마다 날수가 다르고, 윤년이 있으며, 그레고리력이 처음 시행된 1582년 10월에는 4일 다음 날이 15일이었습니다. 이런 일은 직접 계산하지 말고 `datetime` 모듈에 맡기는 것이 현명합니다.

**문제** 두 줄에 걸쳐 날짜가 `YYYY-MM-DD` 형식으로 주어집니다. 첫째 줄에 첫 날짜의 요일(`월요일`~`일요일`)을, 둘째 줄에 첫 날짜에서 둘째 날짜까지의 날수(둘째 − 첫째, 음수 가능)를 출력하십시오.

**제한** 연도는 1 이상 9999 이하

**예제 입력**

```
2026-11-23
2027-01-01
```

**예제 출력**

```
월요일
39
```

<details>
<summary>💡 힌트 보기</summary>

`date.fromisoformat(문자열)`로 날짜 객체를 만들고, 두 날짜를 빼면 `timedelta`가 나옵니다. 그 `.days`가 날수입니다. 요일은 `.weekday()`(월요일이 0)입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from datetime import date
d1 = date.fromisoformat(input())
d2 = date.fromisoformat(input())
print("월화수목금토일"[d1.weekday()] + "요일")
print((d2 - d1).days)
```

`date` 객체끼리의 뺄셈, 비교, 정렬이 모두 자연스럽게 동작합니다. 2024년은 윤년이라 2월 28일과 3월 1일 사이에 2월 29일이 끼어 있어, 숨은 테스트의 답은 −1이 아니라 −2입니다. `datetime`은 그레고리력을 과거로 연장한 달력(proleptic Gregorian)을 씁니다. 그래서 1582년 이전 날짜는 역사 기록과 다를 수 있습니다. 요일 이름을 `"월화수목금토일"[i]`처럼 문자열 인덱싱으로 고르는 요령도 기억해 둘 만합니다.

</details>

## 094. 정확한 제곱근

실수(float)는 유효숫자를 약 15~16자리까지만 기억합니다. 그래서 아주 큰 정수에 `** 0.5`를 쓰면 끝자리가 틀어집니다. `math.isqrt`는 정수만으로 계산하므로 몇 자리든 정확합니다.

**문제** 정수 n이 주어질 때 ⌊√n⌋(제곱해서 n을 넘지 않는 가장 큰 정수)를 출력하십시오.

**제한** 0 ≤ n ≤ 10⁴⁰

**예제 입력 1**

```
10
```

**예제 출력 1**

```
3
```

**예제 입력 2**

```
1000000000000000000000000000000000000
```

**예제 출력 2**

```
1000000000000000000
```

<details>
<summary>💡 힌트 보기</summary>

`math.isqrt(n)`을 쓰십시오. `int(n ** 0.5)`가 어떤 입력에서 틀리는지도 직접 확인해 보십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import math
print(math.isqrt(int(input())))
```

예를 들어 n = (10⁸ + 1)² − 1, 겨우 17자리 수에 대해 `int(n ** 0.5)`는 10⁸이 아니라 10⁸ + 1을 답합니다. 실수로 바꾸는 순간 끝자리 정보가 사라지기 때문입니다. `isqrt`는 뉴턴 방법을 정수로만 수행하여 언제나 정확한 값을 줍니다. 경시 문제에서 '어떤 수가 완전제곱수인가'를 판정할 때는 반드시 `isqrt(n) ** 2 == n`을 쓰십시오.

</details>

## 095. bisect로 세기

20번 문제에서 예고했던 `bisect` 모듈입니다. 정렬된 리스트에서 어떤 값이 들어갈 자리를 **이분 탐색**으로 찾아 줍니다. 백만 개 중에서도 20번 남짓 비교하면 됩니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수, 셋째 줄에 질의 수 Q, 이어서 Q줄에 정수 x가 주어집니다. 각 질의마다 N개의 수 가운데 **x 이하인 수의 개수**를 출력하십시오.

**제한** 1 ≤ N, Q ≤ 10⁵, |각 수| ≤ 10⁹

**예제 입력**

```
5
9 3 1 7 3
3
3
0
10
```

**예제 출력**

```
3
0
5
```

<details>
<summary>💡 힌트 보기</summary>

먼저 정렬한 뒤 `bisect_right(a, x)`를 쓰십시오. x와 같은 값들 **오른쪽**의 위치, 곧 x 이하인 원소의 개수를 돌려줍니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
from bisect import bisect_right
input = sys.stdin.readline
n = int(input())
a = sorted(map(int, input().split()))
q = int(input())
print("\n".join(str(bisect_right(a, int(input()))) for _ in range(q)))
```

질의마다 리스트를 처음부터 훑으면 10⁵ × 10⁵ = 100억 번이 걸리지만, 정렬 한 번(N log N) 뒤 이분 탐색(질의당 log N)을 하면 순식간입니다. `bisect_left`는 x 미만인 개수, `bisect_right`는 x 이하인 개수입니다. 둘의 차가 곧 x의 개수입니다. 제2부 '이분 탐색'에서 이 원리를 직접 구현해 봅니다.

</details>
