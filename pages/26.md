## 126. 이분 탐색 손으로 짜기

1946년에 처음 소개된 이분 탐색이 버그 없이 출판된 것은 1962년의 일이라는 이야기가 있습니다. 2006년에는 자바 표준 라이브러리의 이분 탐색에서조차 오버플로 버그가 발견되었습니다. 단순해 보이지만 경계를 정확히 다루기는 생각보다 어렵습니다.

**문제** 첫째 줄에 N, 둘째 줄에 오름차순으로 정렬된 N개의 정수(중복 가능), 셋째 줄에 Q, 이어서 Q줄에 정수 x가 주어집니다. 각 x가 **처음 나타나는 위치**(1부터)를 출력하고, 없으면 −1을 출력하십시오. `bisect`를 쓰지 말고 직접 구현하십시오.

**제한** 1 ≤ N, Q ≤ 10⁵, |각 수| ≤ 10⁹

**예제 입력**

```
6
1 3 3 3 7 9
4
3
9
4
-5
```

**예제 출력**

```
2
6
-1
-1
```

<details>
<summary>💡 힌트 보기</summary>

구간 [lo, hi)를 두고 `a[mid] < x`이면 lo = mid + 1, 아니면 hi = mid로 줄이십시오. 끝나면 lo는 'x 이상인 첫 위치'입니다. 그 자리에 x가 있는지 확인하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline

def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

n = int(input())
a = list(map(int, input().split()))
out = []
for _ in range(int(input())):
    x = int(input())
    i = lower_bound(a, x)
    out.append(i + 1 if i < n and a[i] == x else -1)
print("\n".join(map(str, out)))
```

반열린 구간 [lo, hi)를 쓰면 '찾는 값이 없을 때'와 '맨 끝보다 클 때'를 따로 다루지 않아도 됩니다. lo는 언제나 'x 이상인 첫 원소의 위치'(없으면 N)로 수렴합니다. 이것이 `bisect_left`가 하는 일입니다. 반복할 때마다 구간이 절반으로 줄기 때문에 10⁵개에서도 17번이면 끝납니다. 자바의 버그는 `(lo + hi) / 2`가 정수 범위를 넘어 음수가 된 것이었습니다. 파이썬에서는 일어나지 않지만, 다른 언어에서는 `lo + (hi - lo) / 2`로 써야 합니다.

</details>

## 127. 업다운 게임

'1부터 100 사이의 수를 맞혀 봐. 틀리면 더 큰지 작은지 알려 줄게.' 가장 똑똑하게 질문하면 최악의 경우 몇 번 만에 맞힐 수 있을까요? 매번 가운데를 묻는 것이 최선이고, 그 답은 2의 거듭제곱과 관련이 있습니다.

**문제** 1 이상 N 이하의 수 하나를 맞히려 합니다. 추측할 때마다 정답, 업, 다운 중 하나를 듣습니다. 최선의 전략으로 **최악의 경우에도 반드시 맞히는** 데 필요한 추측 횟수를 출력하십시오.

**제한** 1 ≤ N ≤ 10¹⁸

**예제 입력 1**

```
100
```

**예제 출력 1**

```
7
```

**예제 입력 2**

```
1
```

**예제 출력 2**

```
1
```

<details>
<summary>💡 힌트 보기</summary>

k번의 추측으로 구별할 수 있는 수는 최대 1 + 2 + 4 + … + 2^(k−1) = 2^k − 1개입니다. 2^k − 1 ≥ N인 가장 작은 k를 구하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
print(n.bit_length())
```

첫 추측은 1개를 확인하고 나머지를 두 쪽으로 나눕니다. 그래서 k번이면 2ᵏ − 1개까지 감당할 수 있습니다. 2ᵏ − 1 ≥ N인 가장 작은 k는 N을 2진수로 썼을 때의 자릿수, 곧 `N.bit_length()`와 같습니다. `math.log2`로 계산하면 N = 2ᵏ 근처에서 실수 오차가 생길 수 있습니다. 정수 연산만으로 답하는 `bit_length()`가 안전합니다. 10¹⁸개 중에서도 60번이면 충분합니다. 이분 탐색의 위력을 실감할 수 있는 숫자입니다.

</details>

## 128. k제곱근

94번의 `math.isqrt`는 제곱근만 다룹니다. 세제곱근이나 10제곱근의 정수 부분이 필요하면 직접 만들어야 합니다. 이분 탐색은 '답이 될 수 있는 정수'의 범위를 반씩 줄여 나가는 가장 믿을 만한 방법입니다.

**문제** 정수 n과 k가 주어질 때, xᵏ ≤ n을 만족하는 가장 큰 정수 x를 출력하십시오.

**제한** 0 ≤ n ≤ 10¹⁰⁰, 2 ≤ k ≤ 100

**예제 입력 1**

```
27 3
```

**예제 출력 1**

```
3
```

**예제 입력 2**

```
1000000 6
```

**예제 출력 2**

```
10
```

<details>
<summary>💡 힌트 보기</summary>

lo = 0, hi = n + 1(또는 더 작은 상한)로 두고, `mid ** k <= n`이면 lo = mid, 아니면 hi = mid로 줄이십시오. 정수 연산만 쓰므로 오차가 없습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n, k = map(int, input().split())
lo, hi = 0, 1 << (n.bit_length() // k + 1)
while hi - lo > 1:
    mid = (lo + hi) // 2
    if mid ** k <= n:
        lo = mid
    else:
        hi = mid
print(lo)
```

불변식은 'lo^k ≤ n < hi^k'입니다. 이 성질을 반복 내내 유지하면서 hi − lo = 1이 될 때까지 줄이면 lo가 답입니다. 어떤 값을 lo에, 어떤 값을 hi에 넣을지를 이 불변식이 결정해 줍니다. 상한을 n + 1로 잡으면 10¹⁰⁰에서 약 330번 반복하지만, n의 비트 수를 k로 나누어 상한을 잡으면 훨씬 줄어듭니다. `round(n ** (1/k))`는 실수 오차 때문에 큰 수에서 틀립니다. 마지막 두 숨은 테스트가 그 함정입니다.

</details>

## 129. 예산 안의 짝

정렬된 두 목록에서 조건을 만족하는 짝을 세는 문제는 두 가지 방법으로 풀 수 있습니다. 이분 탐색을 여러 번 하는 방법과, 두 손가락을 반대 방향으로 움직이는 방법입니다. 둘 다 알아 두면 문제를 보는 눈이 넓어집니다.

**문제** 첫째 줄에 N, M, X, 둘째 줄에 N개의 정수 A, 셋째 줄에 M개의 정수 B가 주어집니다. a + b ≤ X인 쌍 (a ∈ A, b ∈ B)의 개수를 출력하십시오. (같은 값이라도 위치가 다르면 다른 원소입니다.)

**제한** 1 ≤ N, M ≤ 10⁵, |각 수|, |X| ≤ 10⁹

**예제 입력**

```
3 4 10
1 5 9
2 5 8 1
```

**예제 출력**

```
8
```

<details>
<summary>💡 힌트 보기</summary>

B를 정렬한 뒤 A의 각 원소 a마다 `bisect_right(B, X - a)`를 더하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from bisect import bisect_right
n, m, x = map(int, input().split())
a = list(map(int, input().split()))
b = sorted(map(int, input().split()))
print(sum(bisect_right(b, x - v) for v in a))
```

이분 탐색 방식은 O((N + M) log M)입니다. 투 포인터 방식으로는 A를 오름차순, B를 내림차순으로 훑습니다. a가 커질수록 허용되는 b의 최댓값 X − a가 작아지므로 B의 손가락은 한 방향으로만 움직이고, 정렬 후 O(N + M)이 됩니다. 답은 최대 10¹⁰이라 32비트 정수를 넘습니다. 다른 언어로 옮길 때는 64비트 정수를 써야 합니다.

</details>

## 130. 방정식의 근

5차 이상의 방정식에는 일반적인 근의 공식이 없다는 것을 1824년 아벨이 증명했습니다. 그렇다고 근을 구할 수 없는 것은 아닙니다. 연속인 함수의 부호가 바뀌는 구간을 반씩 좁혀 가는 **이분법**은 어떤 방정식에도 쓸 수 있는 든든한 도구입니다.

**문제** 정수 C가 주어질 때 방정식 x³ + x = C의 실수 근을 소수점 아래 넷째 자리까지 반올림해 출력하십시오. (x³ + x는 증가 함수이므로 실수 근은 하나뿐입니다.)

**제한** |C| ≤ 10⁹

**예제 입력 1**

```
2
```

**예제 출력 1**

```
1.0000
```

**예제 입력 2**

```
10
```

**예제 출력 2**

```
2.0000
```

**예제 입력 3**

```
0
```

**예제 출력 3**

```
0.0000
```

<details>
<summary>💡 힌트 보기</summary>

근은 −1000과 1000 사이에 있습니다. 구간의 가운데에서 함숫값과 C를 비교해 반쪽을 버리는 일을 100번 반복하면 실수가 표현할 수 있는 한계까지 정확해집니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
c = int(input())
lo, hi = -1001.0, 1001.0
for _ in range(100):
    mid = (lo + hi) / 2
    if mid ** 3 + mid < c:
        lo = mid
    else:
        hi = mid
x = (lo + hi) / 2
if abs(x) < 5e-5:
    x = 0.0
print(f"{x:.4f}")
```

정수에서는 '구간 길이가 1이 될 때까지' 반복했지만, 실수에서는 정해진 횟수만큼 반복하는 것이 안전합니다. 구간 길이는 2002 / 2¹⁰⁰으로, 실수의 정밀도보다 훨씬 작아집니다. C = 0일 때 근이 아주 작은 음수로 계산되면 `-0.0000`이 출력되는 함정이 있습니다. 반올림한 결과가 0이 될 값은 0.0으로 바로잡아 이를 막았습니다. 뉴턴 방법 x ← x − f(x)/f'(x)는 훨씬 빨리 수렴하지만, 출발점을 잘못 고르면 발산할 수 있습니다. 이분법은 느리지만 결코 배신하지 않습니다.

</details>
