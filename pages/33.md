## 161. 역순쌍과 병합 정렬

122번에서 거품 정렬의 교환 횟수가 역순쌍의 개수임을 보았습니다. N이 20만이면 O(N²)으로는 셀 수 없습니다. 병합 정렬은 두 반쪽을 합치는 순간 '오른쪽 원소가 먼저 나가면, 왼쪽에 남은 원소 수만큼 역순쌍이 있다'는 사실로 역순쌍을 한꺼번에 셉니다.

**문제** 길이 N의 수열에서 i < j이고 aᵢ > aⱼ인 쌍 (i, j)의 개수를 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다.

**출력** 역순쌍의 개수를 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, |aᵢ| ≤ 10⁹, 시간 제한 3초

**예제 입력 1**

```
5
3 1 2 5 4
```

**예제 출력 1**

```
3
```

**예제 입력 2**

```
4
2 2 1 1
```

**예제 출력 2**

```
4
```

<details>
<summary>💡 힌트 보기</summary>

`sort_count(a)`가 (정렬된 리스트, 역순쌍 수)를 돌려주게 하십시오. 두 반쪽을 병합할 때 오른쪽 원소가 왼쪽 원소보다 **엄격하게 작아서** 먼저 나가면, 왼쪽에 남은 원소의 개수를 더합니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
sys.setrecursionlimit(10000)

def sort_count(a):
    if len(a) <= 1:
        return a, 0
    mid = len(a) // 2
    left, x = sort_count(a[:mid])
    right, y = sort_count(a[mid:])
    merged, inv = [], x + y
    i = j = 0
    nl = len(left)
    while i < nl and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
            inv += nl - i
    merged += left[i:]
    merged += right[j:]
    return merged, inv

input = sys.stdin.readline
n = int(input())
print(sort_count(list(map(int, input().split())))[1])
```

병합할 때 `left[i] <= right[j]`에서 등호를 왼쪽에 주어야 같은 값끼리는 역순쌍으로 세지 않습니다. 예제 2의 답이 4인 것을 이 등호 하나가 결정합니다. 재귀 깊이는 log₂N ≈ 18이라 재귀 한도는 문제가 되지 않습니다. 시간은 O(N log N)입니다. 분할 정복의 세 단계, 곧 **나누고(divide), 각각 풀고(conquer), 합치는(combine)** 단계 가운데 이 문제의 핵심은 '합치는 단계에서 두 반쪽에 걸친 답을 센다'는 데 있습니다.

</details>

## 162. 목재 재단

'최대 길이 L은 얼마인가?'라는 질문을 'L로 잘랐을 때 N조각 이상 나오는가?'라는 예/아니오 질문으로 바꾸어 봅니다. L이 커질수록 조각 수는 줄어드므로 답은 어느 지점에서 '예'에서 '아니오'로 바뀝니다. 그 경계를 이분 탐색으로 찾는 것이 **매개 변수 탐색**입니다.

**문제** 길이가 제각각인 통나무 K개를 모두 같은 정수 길이 L로 잘라 N조각 이상을 만들려 합니다(남는 토막은 버립니다). 가능한 L의 최댓값을 구하십시오. L = 1이면 언제나 가능하도록 입력이 주어집니다.

**입력** 첫째 줄에 K와 N, 둘째 줄에 K개의 통나무 길이가 주어집니다.

**출력** L의 최댓값을 출력합니다.

**제한** 1 ≤ K ≤ 10⁵, 1 ≤ N ≤ 10¹¹, 1 ≤ 길이 ≤ 2³¹ − 1, 시간 제한 2초

**예제 입력**

```
4 11
802 743 457 539
```

**예제 출력**

```
200
```

<details>
<summary>💡 힌트 보기</summary>

`pieces(L) = sum(x // L for x in 통나무)`는 L에 대해 감소합니다. pieces(L) ≥ N을 만족하는 가장 큰 L을 이분 탐색으로 찾으십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
k, n = map(int, input().split())
logs = list(map(int, input().split()))
lo, hi = 1, max(logs) + 1
while hi - lo > 1:
    mid = (lo + hi) // 2
    if sum(x // mid for x in logs) >= n:
        lo = mid
    else:
        hi = mid
print(lo)
```

불변식 'pieces(lo) ≥ N, pieces(hi) < N'을 유지합니다(128번과 같은 구조). lo = 1은 문제 조건에 따라 언제나 가능하고, hi = 최댓값 + 1은 언제나 불가능합니다. 판정 한 번에 O(K), 이분 탐색은 약 31번이므로 전체 O(K log(최댓값))입니다. '최댓값을 구하라'를 '이 값이 가능한가?'로 바꾸는 발상은 경시 문제에서 가장 강력한 도구 가운데 하나입니다. 판정 함수가 **단조**인지 확인하는 것이 출발점입니다.

</details>

## 163. 등대지기

해안선 위의 후보지 N곳 가운데 C곳에 등대를 세우려 합니다. 등대끼리 너무 가까우면 빛이 겹쳐 낭비이니, **가장 가까운 두 등대 사이의 거리**를 최대로 하고 싶습니다. '최소의 최대화'는 매개 변수 탐색의 단골 손님입니다.

**문제** 수직선 위의 서로 다른 N개 위치 가운데 C곳을 골라 등대를 세울 때, 가장 가까운 두 등대 사이 거리의 최댓값을 구하십시오.

**입력** 첫째 줄에 N과 C, 둘째 줄에 N개의 위치가 주어집니다.

**출력** 가장 가까운 두 등대 사이 거리의 최댓값을 출력합니다.

**제한** 2 ≤ C ≤ N ≤ 2×10⁵, 0 ≤ 위치 ≤ 10⁹, 시간 제한 3초

**예제 입력**

```
5 3
1 2 8 4 9
```

**예제 출력**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

거리 D가 주어지면 '왼쪽부터 가능한 한 일찍, 직전 등대에서 D 이상 떨어진 곳마다 세우는' 그리디로 몇 개를 세울 수 있는지 알 수 있습니다. 그 개수가 C 이상인 가장 큰 D를 이분 탐색하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
n, c = map(int, input().split())
x = sorted(map(int, input().split()))

def can(d):
    count, last = 1, x[0]
    for p in x:
        if p - last >= d:
            count += 1
            last = p
            if count >= c:
                return True
    return False

lo, hi = 1, x[-1] - x[0] + 1
while hi - lo > 1:
    mid = (lo + hi) // 2
    if can(mid):
        lo = mid
    else:
        hi = mid
print(lo)
```

판정 함수 안에서 '가능한 한 일찍 세우는' 그리디가 옳은 이유도 교환 논증입니다. 어떤 배치에서 첫 등대를 더 왼쪽으로 옮겨도 나머지와의 거리는 늘어나기만 합니다. 매개 변수 탐색 바깥에서 이분 탐색, 안쪽에서 그리디, 이렇게 두 기법이 겹쳐 쓰였습니다. 실전 문제는 대개 이렇게 여러 기법의 조합입니다. C개를 채우는 순간 바로 `True`를 돌려주는 조기 종료가 파이썬에서는 꽤 큰 시간 차이를 만듭니다.

</details>

## 164. 거대한 피보나치

F(10¹⁸)은 상상할 수 없을 만큼 큰 수이지만, 그 나머지는 60번 남짓의 행렬 곱셈으로 구할 수 있습니다. 피보나치의 점화식을 2×2 행렬의 거듭제곱으로 바꾸고, 105번의 빠른 거듭제곱을 행렬에 그대로 적용하면 됩니다.

**문제** n이 주어질 때 F(n)을 1,000,000,007로 나눈 나머지를 구하십시오. F(0) = 0, F(1) = 1입니다.

**입력** 첫째 줄에 n이 주어집니다.

**출력** F(n) mod 1,000,000,007을 출력합니다.

**제한** 0 ≤ n ≤ 10¹⁸, 시간 제한 1초

**예제 입력 1**

```
10
```

**예제 출력 1**

```
55
```

**예제 입력 2**

```
1000
```

**예제 출력 2**

```
517691607
```

<details>
<summary>💡 힌트 보기</summary>

[[1, 1], [1, 0]]ⁿ = [[F(n+1), F(n)], [F(n), F(n−1)]]입니다. 행렬 곱셈 함수를 만들고 105번처럼 지수를 2진수로 쪼개어 거듭제곱하십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
MOD = 1_000_000_007

def mul(A, B):
    return [[(A[0][0] * B[0][0] + A[0][1] * B[1][0]) % MOD, (A[0][0] * B[0][1] + A[0][1] * B[1][1]) % MOD],
            [(A[1][0] * B[0][0] + A[1][1] * B[1][0]) % MOD, (A[1][0] * B[0][1] + A[1][1] * B[1][1]) % MOD]]

n = int(input())
result = [[1, 0], [0, 1]]
base = [[1, 1], [1, 0]]
while n:
    if n & 1:
        result = mul(result, base)
    base = mul(base, base)
    n >>= 1
print(result[0][1])
```

점화식 (F(n+1), F(n)) = M × (F(n), F(n−1))을 n번 적용하는 것이 Mⁿ을 곱하는 것과 같다는 데서 출발합니다. 곱셈 결합 법칙 덕분에 Mⁿ을 O(log n)번의 행렬 곱으로 계산할 수 있습니다. 이 기법은 '선형 점화식이면 무엇이든' 적용됩니다. 예를 들어 a(n) = 2a(n−1) + 3a(n−3) 같은 점화식도 3×3 행렬로 같은 방식으로 풀 수 있습니다. 숨은 테스트의 2000000016은 1,000,000,007에 대한 피보나치 수열의 주기(피사노 주기)와 관련된 값입니다.

</details>

## 165. 곱셈표의 K번째 수

N×N 곱셈표에는 N² = 10¹⁰개의 수가 있어서 정렬은커녕 만들 수조차 없습니다. 하지만 'x 이하인 수가 몇 개인가?'는 행마다 min(N, x // i)를 더하면 O(N)에 답할 수 있습니다. 이 개수 함수 위에서 이분 탐색을 하면 됩니다.

**문제** N×N 곱셈표(i행 j열의 값은 i × j)의 모든 수를 오름차순으로 늘어놓았을 때 K번째 수를 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 K가 주어집니다.

**출력** K번째 수를 출력합니다.

**제한** 1 ≤ N ≤ 10⁵, 1 ≤ K ≤ N², 시간 제한 3초

**예제 입력 1**

```
3
7
```

**예제 출력 1**

```
6
```

**예제 입력 2**

```
4
16
```

**예제 출력 2**

```
16
```

<details>
<summary>💡 힌트 보기</summary>

`count(x) = Σ min(N, x // i)` (i = 1..N)는 x 이하인 수의 개수입니다. count(x) ≥ K인 가장 작은 x가 답입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
k = int(input())
lo, hi = 0, min(n * n, k)
while hi - lo > 1:
    mid = (lo + hi) // 2
    cnt = 0
    for i in range(1, min(n, mid) + 1):
        cnt += min(n, mid // i)
    if cnt >= k:
        hi = mid
    else:
        lo = mid
print(hi)
```

K번째 수는 K를 넘을 수 없습니다(1행에만 1, 2, …, N이 있고, 각 값 v 이하에는 적어도 v개의 수가 있기 때문입니다). 그래서 상한을 min(N², K)로 잡아 반복 횟수를 줄였습니다. 답이 곱셈표에 실제로 있는 수인지 걱정할 수 있습니다. count가 처음으로 K 이상이 되는 x는 반드시 표에 있는 값입니다. x가 표에 없다면 count(x) = count(x − 1)이라 더 작은 x에서 이미 K 이상이 되었을 것이기 때문입니다. 판정 한 번에 O(N), 이분 탐색 약 34번입니다.

</details>
