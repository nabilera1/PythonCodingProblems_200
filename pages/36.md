## 176. 그리디가 실패하는 동전

12번에서 1, 3, 4원짜리 동전으로 6원을 만들 때 탐욕법은 3개(4+1+1)를 쓰지만 최적은 2개(3+3)라는 반례를 보았습니다. 동전 체계가 '정규적'이지 않으면 동적 계획법만이 정답을 보장합니다.

**문제** N종류의 동전(각각 무한히 많음)으로 정확히 K원을 만들 때 필요한 동전의 최소 개수를 구하십시오. 만들 수 없으면 −1을 출력합니다.

**입력** 첫째 줄에 N과 K, 둘째 줄에 N개의 동전 액면가가 주어집니다.

**출력** 최소 개수 또는 −1을 출력합니다.

**제한** 1 ≤ N ≤ 100, 1 ≤ K ≤ 10⁴, 1 ≤ 액면가 ≤ 10⁴, 시간 제한 3초

**예제 입력 1**

```
3 6
1 3 4
```

**예제 출력 1**

```
2
```

**예제 입력 2**

```
2 3
2 5
```

**예제 출력 2**

```
-1
```

<details>
<summary>💡 힌트 보기</summary>

best[v] = v원을 만드는 최소 개수. best[0] = 0이고, best[v] = min(best[v − c] + 1)입니다. 동전마다 v를 **작은 쪽부터** 올라가며 갱신하면 같은 동전을 여러 번 쓸 수 있습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n, k = map(int, input().split())
coins = list(map(int, input().split()))
INF = 1 << 30
best = [0] + [INF] * k
for c in coins:
    for v in range(c, k + 1):
        t = best[v - c] + 1
        if t < best[v]:
            best[v] = t
print(best[k] if best[k] < INF else -1)
```

174번 0-1 배낭과의 차이는 **갱신 방향** 하나입니다. 작은 쪽부터 갱신하면 `best[v − c]`가 이미 같은 동전을 쓴 결과일 수 있으므로, 동전을 몇 번이든 쓸 수 있는 문제가 됩니다. 예제 1은 12번 해설의 반례 그대로입니다. 탐욕법이 언제 옳은지(동전 체계의 정규성)를 판정하는 문제는 그 자체로 흥미로운 연구 주제입니다. 만들 수 없는 금액을 무한대로 남겨 두고 마지막에 −1로 바꾸는 방식은 '불가능' 상태를 다루는 동적 계획법의 표준입니다.

</details>

## 177. 행렬 곱셈의 순서

행렬 곱셈은 결합 법칙이 성립하므로 (AB)C와 A(BC)의 결과는 같습니다. 하지만 곱셈 횟수는 수십 배까지 차이 날 수 있습니다. 구간 [i, j]를 어디서 마지막으로 나눌지 정하는 **구간 동적 계획법**의 대표 문제입니다.

**문제** N개의 행렬 A₁, …, A_N의 곱을 계산하려 합니다. Aᵢ의 크기는 dᵢ₋₁ × dᵢ입니다. p×q 행렬과 q×r 행렬을 곱하는 데 p×q×r번의 곱셈이 필요할 때, 전체 곱셈 횟수의 최솟값을 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N+1개의 정수 d₀, d₁, …, d_N이 주어집니다.

**출력** 최소 곱셈 횟수를 출력합니다.

**제한** 1 ≤ N ≤ 200, 1 ≤ dᵢ ≤ 500, 시간 제한 3초

**예제 입력**

```
3
10 30 5 60
```

**예제 출력**

```
4500
```

<details>
<summary>💡 힌트 보기</summary>

C[i][j] = Aᵢ…Aⱼ의 최소 비용. 마지막 곱셈이 k에서 갈라진다면 C[i][k] + C[k+1][j] + dᵢ₋₁·d_k·dⱼ입니다. 구간 길이가 짧은 것부터 채우십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
d = list(map(int, input().split()))
INF = float('inf')
C = [[0] * n for _ in range(n)]
for length in range(2, n + 1):
    for i in range(n - length + 1):
        j = i + length - 1
        di, dj = d[i], d[j + 1]
        Ci = C[i]
        best = INF
        for k in range(i, j):
            t = Ci[k] + C[k + 1][j] + di * d[k + 1] * dj
            if t < best:
                best = t
        Ci[j] = best
print(C[0][n - 1])
```

예제에서 (A₁A₂)A₃는 10·30·5 + 10·5·60 = 4500번, A₁(A₂A₃)는 30·5·60 + 10·30·60 = 27000번입니다. 순서만 바꿨는데 여섯 배 차이가 납니다. 구간 [i, j]의 답은 더 짧은 구간들의 답에만 의존하므로 **길이 순서**로 채우는 것이 핵심입니다. 왼쪽 위에서 오른쪽 아래로 채우는 평범한 순서로는 아직 계산하지 않은 칸을 읽게 됩니다. 상태 O(N²)개, 상태마다 O(N)이므로 전체 O(N³)이며, N = 200에서 약 130만 번입니다.

</details>

## 178. 회문 분할

문자열을 모두 회문인 조각으로 자르되 조각 수를 최소로 하려 합니다. '어디까지가 회문인가'와 '몇 조각으로 자를까'라는 두 질문이 얽혀 있지만, 회문의 **중심에서 바깥으로 넓혀 가면** 두 질문을 한 번에 처리할 수 있습니다.

**문제** 영어 소문자로 된 문자열을 회문인 조각들로 나눌 때 조각 수의 최솟값을 구하십시오.

**입력** 첫째 줄에 문자열이 주어집니다.

**출력** 최소 조각 수를 출력합니다.

**제한** 1 ≤ 길이 ≤ 2000, 시간 제한 3초

**예제 입력 1**

```
banana
```

**예제 출력 1**

```
2
```

**예제 입력 2**

```
abc
```

**예제 출력 2**

```
3
```

<details>
<summary>💡 힌트 보기</summary>

D[i] = 앞의 i글자를 나누는 최소 조각 수. 중심 c마다 회문을 양쪽으로 넓히며, s[l..r]이 회문일 때마다 D[r+1] = min(D[r+1], D[l] + 1)로 갱신하십시오. 홀수 길이와 짝수 길이 중심을 모두 보아야 합니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
s = input()
n = len(s)
D = list(range(n + 1))
for c in range(n):
    for l, r in ((c, c), (c, c + 1)):
        while l >= 0 and r < n and s[l] == s[r]:
            if D[l] + 1 < D[r + 1]:
                D[r + 1] = D[l] + 1
            l -= 1
            r += 1
print(D[n])
```

중심을 왼쪽부터 처리하면 D[l]을 읽는 시점에 그 값이 이미 확정되어 있습니다. l 앞에서 끝나는 회문들은 모두 더 왼쪽에 중심이 있기 때문입니다. 갱신 순서가 옳다는 것을 이렇게 확인하는 것이 동적 계획법 설계의 핵심입니다. 확장하는 횟수는 모든 회문 부분 문자열의 개수와 같아 최악(`aaa…`)에 약 n²/2 = 200만 번입니다. 'banana'는 b | anana의 2조각입니다. D를 `range(n + 1)`로 초기화한 것은 '한 글자씩 자르면 언제나 가능하다'는 상한입니다.

</details>

## 179. 외판원 순회

모든 도시를 한 번씩 방문하고 출발점으로 돌아오는 최단 경로를 찾는 외판원 문제는 NP-난해 문제의 상징입니다. 도시가 열두 개라면 순열은 4억 가지가 넘지만, '방문한 도시의 집합'을 **비트마스크**로 나타내는 동적 계획법(1962년 벨먼, 헬드–카프)은 수십만 번의 계산으로 답을 찾습니다.

**문제** N개의 도시와 도시 i에서 j로 가는 비용 W[i][j]가 주어집니다(0이면 길이 없음, 방향이 있음). 모든 도시를 정확히 한 번씩 방문하고 출발 도시로 돌아오는 순회의 최소 비용을 구하십시오. 순회가 불가능하면 −1을 출력합니다.

**입력** 첫째 줄에 N, 이어서 N줄에 비용 행렬이 주어집니다.

**출력** 최소 비용 또는 −1을 출력합니다.

**제한** 2 ≤ N ≤ 12, 0 ≤ W[i][j] ≤ 10⁶, W[i][i] = 0, 시간 제한 4초

**예제 입력 1**

```
4
0 3 0 7
2 0 4 0
0 5 0 1
6 0 2 0
```

**예제 출력 1**

```
14
```

**예제 입력 2**

```
3
0 1 0
0 0 1
0 0 0
```

**예제 출력 2**

```
-1
```

<details>
<summary>💡 힌트 보기</summary>

dp[mask][v] = 도시 0에서 출발해 mask에 속한 도시들을 방문하고 지금 v에 있을 때의 최소 비용. 순회는 순환이므로 출발 도시를 0으로 고정해도 됩니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
input = sys.stdin.readline
n = int(input())
W = [list(map(int, input().split())) for _ in range(n)]
INF = float('inf')
FULL = 1 << n
dp = [[INF] * n for _ in range(FULL)]
dp[1][0] = 0
for mask in range(1, FULL, 2):
    row = dp[mask]
    for v in range(n):
        cur = row[v]
        if cur == INF:
            continue
        Wv = W[v]
        for u in range(n):
            if mask >> u & 1 or Wv[u] == 0:
                continue
            nm = mask | 1 << u
            if cur + Wv[u] < dp[nm][u]:
                dp[nm][u] = cur + Wv[u]
best = min((dp[FULL - 1][v] + W[v][0] for v in range(1, n) if W[v][0]), default=INF)
print(best if best < INF else -1)
```

상태는 2ᴺ × N개, 상태마다 N개의 다음 도시를 보므로 O(2ᴺ·N²)입니다. N = 12에서 약 59만 번으로, 순열 11! ≈ 4천만 개를 모두 보는 것과 비교하면 70배 가까이 빠릅니다. 도시 0을 언제나 포함한 mask(홀수)만 살펴보면 되므로 `range(1, FULL, 2)`로 절반을 건너뛰었습니다. 예제 1에서 도시를 1번부터 세면 최적 순회는 1 → 2 → 3 → 4 → 1(3 + 4 + 1 + 6 = 14)이고, 반대 방향 1 → 4 → 3 → 2 → 1은 7 + 2 + 5 + 2 = 16입니다. 길에 방향이 있으므로 같은 순회라도 도는 방향에 따라 비용이 다릅니다.

</details>

## 180. 서로 이웃하지 않는 마을

트리에서는 한 정점의 답이 자식들의 답으로만 정해집니다. 그래서 잎에서 뿌리 쪽으로 올라오며 계산하는 **트리 동적 계획법**이 자연스럽습니다. 정점마다 '나를 고른 경우'와 '고르지 않은 경우' 두 상태를 들고 올라옵니다.

**문제** N개의 마을이 N−1개의 길로 이어진 트리를 이룹니다. 마을마다 인구가 있습니다. 길로 직접 이어진 두 마을을 함께 고르지 않으면서 고른 마을들의 인구 합을 최대로 하려 합니다. 그 최댓값을 구하십시오.

**입력** 첫째 줄에 N, 둘째 줄에 N개의 인구, 이어서 N−1줄에 길로 이어진 두 마을의 번호(1부터)가 주어집니다.

**출력** 최대 인구 합을 출력합니다.

**제한** 1 ≤ N ≤ 2×10⁵, 1 ≤ 인구 ≤ 10⁴, 시간 제한 3초

**예제 입력**

```
5
1 2 3 4 5
1 2
1 3
3 4
3 5
```

**예제 출력**

```
11
```

<details>
<summary>💡 힌트 보기</summary>

in[v] = v를 고를 때 v의 서브트리 최댓값 = 인구[v] + Σ out[자식], out[v] = v를 고르지 않을 때 = Σ max(in[자식], out[자식]). 재귀 대신, BFS로 얻은 방문 순서를 거꾸로 처리하면 잎부터 계산할 수 있습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
import sys
data = sys.stdin.buffer.read().split()
n = int(data[0])
w = [0] + list(map(int, data[1:1 + n]))
adj = [[] for _ in range(n + 1)]
idx = 1 + n
for _ in range(n - 1):
    a, b = int(data[idx]), int(data[idx + 1])
    idx += 2
    adj[a].append(b)
    adj[b].append(a)
parent = [0] * (n + 1)
order = [1]
parent[1] = -1
for v in order:
    for u in adj[v]:
        if u != parent[v]:
            parent[u] = v
            order.append(u)
inc = w[:]
exc = [0] * (n + 1)
for v in reversed(order):
    p = parent[v]
    if p > 0:
        inc[p] += exc[v]
        exc[p] += inc[v] if inc[v] > exc[v] else exc[v]
print(max(inc[1], exc[1]))
```

`for v in order:` 반복 중에 `order`에 원소를 덧붙이면 자연스럽게 BFS가 됩니다. 그 순서를 거꾸로 돌면 언제나 자식이 부모보다 먼저 처리됩니다. 재귀 없이 트리 DP를 하는 파이썬의 표준 요령입니다. 숨은 테스트에는 20만 개의 마을이 일렬로 이어진 경우가 있습니다. 재귀 DFS라면 깊이 20만에서 파이썬이 멈추지만, 이 방법은 깊이와 상관없이 동작합니다. 예제에서는 2, 4, 5번 마을을 골라 2 + 4 + 5 = 11입니다.

</details>
