## 131. 괄호의 짝

스택은 접시 더미처럼 마지막에 넣은 것을 먼저 꺼냅니다(LIFO). 괄호의 짝 맞추기는 스택을 위해 태어난 문제라 해도 과언이 아닙니다. 가장 최근에 열린 괄호가 가장 먼저 닫혀야 하기 때문입니다.

**문제** `()`, `[]`, `{}`로만 된 문자열이 주어질 때 올바르게 짝지어져 있으면 `YES`, 아니면 `NO`를 출력하십시오.

**제한** 1 ≤ 길이 ≤ 10⁵

**예제 입력 1**

```
{[()()]}
```

**예제 출력 1**

```
YES
```

**예제 입력 2**

```
([)]
```

**예제 출력 2**

```
NO
```

<details>
<summary>💡 힌트 보기</summary>

여는 괄호는 스택에 넣고, 닫는 괄호를 만나면 스택 맨 위가 짝이 맞는 여는 괄호인지 확인한 뒤 꺼내십시오. 끝났을 때 스택이 비어 있어야 합니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
PAIR = {")": "(", "]": "[", "}": "{"}
stack = []
ok = True
for ch in input():
    if ch in "([{":
        stack.append(ch)
    elif not stack or stack.pop() != PAIR[ch]:
        ok = False
        break
print("YES" if ok and not stack else "NO")
```

실패하는 경우는 세 가지입니다. 닫는 괄호가 나왔는데 스택이 비어 있을 때, 짝이 맞지 않을 때, 그리고 끝났는데 열린 괄호가 남아 있을 때입니다. 세 경우를 빠짐없이 검사해야 합니다. 파이썬 리스트의 `append()`와 `pop()`은 맨 뒤에서 일어나므로 매우 빠릅니다. 리스트가 곧 훌륭한 스택입니다. 괄호 한 종류뿐이라면 스택 없이 '열린 괄호 개수' 하나로 충분합니다. 종류가 여럿일 때 스택이 필요한 이유를 생각해 보십시오.

</details>

## 132. 후위 표기법

1924년 폴란드의 논리학자 우카시에비치는 괄호 없이 수식을 쓰는 표기법을 고안했습니다. 연산자를 피연산자 뒤에 두는 '역폴란드 표기법'은 1972년 휴렛팩커드의 공학용 계산기 HP-35에 채택되어 공학자들의 사랑을 받았습니다.

**문제** 후위 표기식이 공백으로 구분된 토큰으로 주어집니다. 토큰은 정수 또는 `+`, `-`, `*`입니다. 식의 값을 출력하십시오. 식은 언제나 올바릅니다.

**제한** 토큰 수 ≤ 10⁴, |정수| ≤ 100

**예제 입력 1**

```
3 4 + 2 *
```

**예제 출력 1**

```
14
```

**예제 입력 2**

```
5 1 2 + 4 * + 3 -
```

**예제 출력 2**

```
14
```

<details>
<summary>💡 힌트 보기</summary>

수는 스택에 넣고, 연산자를 만나면 두 개를 꺼내 계산한 결과를 다시 넣으십시오. 먼저 꺼낸 것이 **오른쪽** 피연산자입니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
stack = []
for t in input().split():
    if t in ("+", "-", "*"):
        b = stack.pop()
        a = stack.pop()
        stack.append(a + b if t == "+" else a - b if t == "-" else a * b)
    else:
        stack.append(int(t))
print(stack[0])
```

`5 1 2 + 4 * + 3 -`는 중위 표기로 5 + (1 + 2) × 4 − 3입니다. 후위 표기에서는 계산 순서가 토큰의 순서 자체에 담겨 있으므로 괄호도 우선순위 규칙도 필요 없습니다. 빼기와 나누기는 순서가 중요하므로 꺼내는 순서를 바꾸면 안 됩니다. `-7 3 -`에서 `-7`은 음수 하나이지 연산자가 아니라는 점도 확인해 보십시오. 중위 표기를 후위 표기로 바꾸는 방법(다익스트라의 차량기지 알고리즘, 1961)도 스택을 씁니다.

</details>

## 133. 카드 버리기

큐는 줄서기처럼 먼저 온 것이 먼저 나갑니다(FIFO). 파이썬 리스트의 `pop(0)`은 뒤의 원소를 모두 당겨야 해서 느립니다. 양쪽 끝을 모두 빠르게 다루는 `collections.deque`를 써야 합니다.

**문제** 1부터 N까지 적힌 카드가 1번이 맨 위에 오도록 쌓여 있습니다. 카드가 한 장 남을 때까지 '맨 위 카드를 버리고, 그다음 맨 위 카드를 맨 아래로 옮기는' 일을 반복합니다. 마지막에 남는 카드를 출력하십시오.

**제한** 1 ≤ N ≤ 5×10⁵

**예제 입력 1**

```
6
```

**예제 출력 1**

```
4
```

**예제 입력 2**

```
1
```

**예제 출력 2**

```
1
```

<details>
<summary>💡 힌트 보기</summary>

`deque(range(1, N + 1))`에서 `popleft()`로 버리고, `append(popleft())`로 맨 아래로 옮기십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from collections import deque
n = int(input())
q = deque(range(1, n + 1))
while len(q) > 1:
    q.popleft()
    q.append(q.popleft())
print(q[0])
```

`deque`의 `popleft()`는 O(1)이지만 리스트의 `pop(0)`은 O(N)입니다. N = 50만에서 리스트로 하면 수천억 번 이동이 필요해 끝나지 않습니다. 시간 제한 안에 끝나려면 **연산마다 비용이 얼마인지** 알고 자료구조를 골라야 합니다. 결과를 표로 그려 보면 규칙이 보입니다. N이 2의 거듭제곱이면 답은 N이고, 그렇지 않으면 2 × (N − 2^⌊log₂N⌋)입니다. 111번 요세푸스 문제의 k = 2인 경우와 닮은꼴입니다.

</details>

## 134. 다음 큰 수

'오른쪽에서 처음 만나는 나보다 큰 수'를 찾는 문제는 주가 분석(며칠 뒤에 오르는가)이나 기온 예보(며칠 뒤에 더 따뜻해지는가)에 그대로 쓰입니다. 비결은 아직 답을 찾지 못한 원소들을 스택에 쌓아 두는 것입니다.

**문제** 첫째 줄에 N, 둘째 줄에 N개의 정수가 주어집니다. 각 원소마다 오른쪽에 있으면서 그보다 큰 수 가운데 가장 가까운 수를 출력하고, 없으면 −1을 출력하십시오.

**제한** 1 ≤ N ≤ 10⁵, 1 ≤ 각 수 ≤ 10⁹

**예제 입력**

```
6
3 5 2 7 7 1
```

**예제 출력**

```
5 7 7 -1 -1 -1
```

<details>
<summary>💡 힌트 보기</summary>

스택에 '아직 답을 찾지 못한 원소의 인덱스'를 쌓아 둡니다. 새 원소가 스택 맨 위 원소보다 크면, 그 원소의 답은 새 원소입니다. 더 이상 작지 않을 때까지 꺼내십시오.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
n = int(input())
a = list(map(int, input().split()))
ans = [-1] * n
stack = []
for i, x in enumerate(a):
    while stack and a[stack[-1]] < x:
        ans[stack.pop()] = x
    stack.append(i)
print(*ans)
```

스택 안의 값들은 언제나 아래에서 위로 갈수록 작거나 같습니다(단조 스택). 이중 반복문처럼 보이지만 각 인덱스는 스택에 한 번 들어가고 한 번 나오므로 전체는 O(N)입니다. 이런 분석을 **분할 상환 분석**이라 합니다. 모든 쌍을 비교하는 O(N²) 풀이는 내림차순으로 정렬된 숨은 테스트에서 시간 초과가 납니다.

</details>

## 135. 우선순위 프린터

공용 프린터에 급한 문서가 들어오면 앞에서 기다리던 문서는 뒤로 밀립니다. 이 규칙을 그대로 흉내 내는 것이 큐 시뮬레이션입니다.

**문제** 첫째 줄에 문서 수 N과 관심 있는 문서의 위치 M(0부터), 둘째 줄에 대기열 앞에서부터 각 문서의 중요도(1~9)가 주어집니다. 프린터는 맨 앞 문서를 꺼내, 대기열에 그보다 중요도가 높은 문서가 하나라도 있으면 맨 뒤로 보내고, 없으면 인쇄합니다. M번 문서가 몇 번째로 인쇄되는지 출력하십시오.

**제한** 1 ≤ N ≤ 100

**예제 입력 1**

```
4 2
1 2 3 4
```

**예제 출력 1**

```
2
```

**예제 입력 2**

```
6 0
1 1 9 1 1 1
```

**예제 출력 2**

```
5
```

<details>
<summary>💡 힌트 보기</summary>

`deque`에 (중요도, 원래 위치) 쌍을 넣고 시뮬레이션하십시오. '더 중요한 문서가 있는가'는 `max()`로 확인할 수 있습니다.

</details>

<details>
<summary>✅ 정답과 해설 보기</summary>

```python
from collections import deque
n, m = map(int, input().split())
q = deque((p, i) for i, p in enumerate(map(int, input().split())))
printed = 0
while q:
    p, i = q.popleft()
    if any(p < other for other, _ in q):
        q.append((p, i))
    else:
        printed += 1
        if i == m:
            print(printed)
            break
```

문서마다 원래 위치를 함께 저장해 두는 것이 핵심입니다. 중요도가 같은 문서가 여럿일 수 있어서 중요도만으로는 어느 문서인지 구별할 수 없기 때문입니다. N이 작아서 매번 대기열 전체를 훑어도 충분합니다. N이 크다면 중요도별 개수를 세어 두거나 힙(`heapq`)을 써서 '남은 최대 중요도'를 빠르게 알아내야 합니다.

</details>
